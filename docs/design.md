# qooMeta 設計メモ

2026-09-19 作成。qooViewer の会話で出た「生成 AI で蔵書のメタデータを自動で付けたい」という要望から、
単独のツールとして切り出したもの。

## 目的と範囲

- 入力は**ファイル名の一覧**(とフォルダ構成)だけ。書庫の中身は開かない。
- 出力は「提案」。最終的な確定は、取り込む側のアプリ(qooViewer のメタデータの編集、StackNest の詳細欄)か、
  このツールの見直し表で利用者が行う。
- 出力先は 2 つ。
  - **qooViewer** の保存データ JSON(formatVersion 4 の `metadata`)。
  - **StackNest**(github.com/shelfsmith/stacknest)が取り込める Stackroom 2.1b のライブラリ XML。

## 処理の流れ

```
scan    フォルダを走査 → 名前を部分に分ける(NameParser)→ 規則でシリーズ候補(SeriesGrouper)
judge   候補 1 組ずつ、端末内モデルが「シリーズか / 名前はどこまでか / 外す本はどれか」を判定(SeriesJudge)
export  判定を本ごとの値へ反映(ProposalFinalizer)→ qooViewer JSON / Stackroom XML
report  手元で開く見直し表(HTML)
```

途中の状態は 1 つの提案ファイル(JSON)に持つ。どの段もこれを読み書きするので、判定を途中で止めても続きから再開できる。

### 名前の解析

想定する形は `(分類) [サークル (作者)] タイトル (ネタ)`。どの部分も省略されうる。括弧は全角も受け付け、
**値の表記(全角・半角)は変えない**(比較のときだけ NFKC に揃える)。

### シリーズの候補(規則)

1. **同じ書き手(サークル。無ければフォルダ名)の中だけで比べる。** 別の書き手の偶然の一致を最初から除く。
2. **1 段目: 「タイトル + 巻」の形の本を、巻を除いた頭でまとめる**(「X 21」「X 第3巻」「X Vol.5」「X 上」)。
   後ろが巻だけでできていることを求めるので、頭は 1 文字でもよい。巻の無い「X」も同じ頭の組に入れ、
   副題付きの「X 〇〇編」も、頭が語の切れ目で一致すれば入れる(`attachesSubtitledBooks`)。
3. **2 段目: 残りを、比較用の形(NFKC・小文字・空白と飾り記号を除く)で並べ替え、隣どうしの共通する前半部分でまとめる。**
4. **文字数の下限(n、既定 4)は、語の途中で切れる一致にだけ掛ける。** 両方とも語の切れ目(空白・記号・数字の手前)で
   切れているなら 1 文字でも同じ組にする。固定の n 文字にしていた頃は、2〜3 文字のタイトル(「咲」「亜人」「風光る」)を
   取りこぼしていた。3 冊目以降を加えて共通部分が縮むときは、語の切れ目で切れる場合だけ加える。
5. ありふれた言葉の疑いとして、同じ前半部分で始まるタイトルを持つ書き手の数を数えておく(判定の参考、見直し表に表示)。
6. **比べる単位は「書き手 + 本の種別(`@mediatype`)」。** 本の種別が違う本(同人の本と商業の単行本など)は同じシリーズにしない。
7. **組にしない例外**(いずれも利用者の指摘から):
   - ネタ(`@genre`)が違う本は分ける。ネタの書かれていない本はいちばん大きい組へ入れる。
   - 語の途中で切れる共通部分が、ひらがなで終わる(助詞で終わる言い回し)、または文字種の 1 続き(1 語だけ)。
   - 2 冊とも一般的な英単語だけでできたタイトル(`/usr/share/dict/words`。後ろに巻があれば組にする)。
   - 版違い・入手経路違いの同じ作品だけの組(下の「版・入手経路・総集編」)。
8. **比べる形**: NFKC・小文字・空白と飾り記号(`_` を含む)を除き、よく使う異体字(凜→凛、髙→高 …)を揃える。
   書き出す名前の表記は変えない。

### シリーズ名の整え方

- 共通部分を元の表記に戻すとき、開いたままの括弧の閉じ括弧(【X】の「】」)と、直後の「!」「?」を含める。
- 末尾の区切り記号は落とすが、先頭の括弧は落とさない。
- 末尾の 1 語が後ろに付く名前を導く語(`side` `part` `episode` `vol` `第` `その` `其ノ` …)なら外す。

### qooLibrary のフォーマット処理

ファイル名は **qooLibrary のファイル名フォーマット処理** で読む(2026-09-19、利用者の指示)。qooLibrary を参照は
せず、必要なソースを `Sources/QooFormat/` に写した(出どころ・写したファイル・変えたところは
`Sources/QooFormat/README.md`)。qooMeta 単独でビルドできる。

- フォーマットは qooLibrary の同人誌のプリセットのもの(`QooLibraryNameParser.doujinshiFormats`)。
  `(@mediatype) [@studio (@author)] @title (@genre) [@keyword]` などを上から照合し、最初に一致したものを採る。
- 先頭の丸括弧が本の種別(`@mediatype`、旧 `@booktype`)かイベント(`@event`)かは、本の種別の語彙との照合で決まる。
- **本の種別の語彙はリポジトリに置かない**(蔵書のフォルダ名と同じ語であることが多い)。利用者の設定
  `~/Library/Application Support/qooMeta-dev/config.json` の `mediaTypes` から渡す。無ければ先頭の丸括弧は
  すべてイベントとして読む(本の種別で分けられなくなるので、scan が注意を出す)。
- **本の種別が違う本は同じシリーズにしない**(比べる単位は「書き手 + 本の種別」)。
- どのフォーマットにも一致しない名前は、qooMeta 自身の解析(NameParser)へ戻す。
- シリーズの候補づくりと巻の読み取りは qooMeta の規則で行う(qooLibrary の SeriesExtractor は写していない)。

### 版・入手経路・総集編(2026-09-19、利用者との取り決め)

- **版**(フルカラー版・カラー版・モノクロ版・完全版・新装版・愛蔵版・修正版・無修正版・改訂版・旧版・新版・〇〇語版):
  内容が違う同じ作品。**入手経路**(DL版・電子版・デジタル版・スキャン版・限定版・初回限定版・特装版・通常版):
  内容は同一で、手に入れた経路だけが違う。特装版・通常版は付録の違いなので入手経路に入れる(両方をそろえる人は稀)。
- どちらの印もシリーズを組むときはタイトルから除いて比べる(EditionMarkers)。印を除いて同じタイトルになる本は同じ作品の
  1 冊と数え、**同じ作品だけの組はシリーズにしない**。シリーズの中の版違いは元の本と同じ巻になる。
- 版は CSV の「版」列と StackNest の Keyword C に書く。入手経路は CSV の「入手元」列だけ。
- **総集編**(「総集編」「総集篇」)は本編と分けて「X 総集編」のシリーズにする。番号の有無で分け方を変えない(番号の無い
  最初の総集編のあとに「総集編2」が出るため)。2 冊以上か、同じ書き手に本編のシリーズ「X」があれば 1 冊でもシリーズにする。
  総集編の前に書かれた収録範囲(「X1~4総集編」)は「X 総集編 1~4」に並べ替えて、範囲をその巻として読む。

### 端末内モデルの判定

- 蔵書全体は渡さない。1 組ずつ、新しいセッションで判定する(macOS 27 で一度に読める量は 8,192 トークン。
  小さなモデルは多数の見比べが苦手)。20 冊を超える組は分けて判定し、結果を合わせる。
- 出力は `@Generable` で形を決める: `isSeries`、`seriesName`、`excludedNumbers`、`confidence`。
- `temperature: 0`。判定できなかった組(安全装置による拒否など)は理由だけを記録し、規則の候補も採らない。

### 巻

シリーズ名より後ろの部分から、読める形だけを読む。**番号の無い本に順番を推測で付けない**(下の 1 巻の推定を除く)。
巻は表記(`volumeText`、文字列)と数(`volumeNumber`、並べ替え用)を分けて持つ。

| 形 | 表記 | 数 |
|---|---|---|
| 数字(`2` `Vol.3` `ver2` `#4` `No.5` `その6` `其ノ7` `第5話` `第2弾` `2つめ` `4冊目`) | 数字 | その数 |
| 「第」+ 数字 + 任意の漢字 1 字(`第1幕` `第三部`) | 数字 | その数 |
| 分冊(`第04-1章` → `04-1`) | `04-1` | 4.1 |
| 合併号・範囲(`36-37号` → `36-37`。後ろが前より大きく差が 3 以内のときだけ) | 範囲 | 最初の数 |
| 漢数字(`その二` `第三話`)。大字(壱弐参 …)・百・千も読む | 漢数字 | その数 |
| ローマ数字(`II` `Ⅳ`。大文字だけ、1〜39) | ローマ数字 | その数 |
| ギリシャ文字(`α` = 1 … `ω` = 24) | 文字 | その数 |
| 末尾の丸括弧の数字(`X (12)`。ネタではなく巻として扱う) | 数字 | その数 |
| 上・中・下、前編・中編・後編(`後編1` のような分冊も) | 語のまま | シリーズに「中」があれば 上1・中2・下3、無ければ 上1・下2(`後編1` = 3.1) |
| 雑誌の号(`2025年36-37号` `2011年03月号` `2022 Vol.01` `_2022-01`) | 号・月 | 号・月。**年はシリーズ名に残す**(1 年ぶんを 1 シリーズ) |

- 漢数字だけで始まる形(`二〇` `三〇`)は、同じシリーズで巻の読めない本が 2 冊以上、互いに違う漢数字で始まるときだけ読む。
- **1 巻の推定**: 2 以上の巻があり 1 巻が無く、番号の無い本が 1 冊に決まるとき、それを 1 巻とみなす(同人誌では 1 冊目に
  番号を付けないことが多い)。番号の無い本が複数なら、タイトルがシリーズ名だけの 1 冊を選ぶ。総集編・番外編などの語や、
  直後の `ex` `sp` などが付く本は候補にしない。ほかの巻の表記に合わせる(`01`、`I`)。推定には `volumeInferred` を付ける。
- 巻の表記・数の元になった判断の多くは StackNest の数字の読み方(MIT)に倣った。

## 出力先ごとの対応

| 項目 | qooViewer JSON | Stackroom XML(StackNest) |
|---|---|---|
| サークル | `author`(著者欄は 1 つ。それまでの手入力の登録と同じ使い方) | `Author` の 1 つ目の値 |
| 作者 | (入らない) | `Author` の 2 つ目以降(StackNest はカンマ区切りを複数値として扱う) |
| タイトル | `title` | `Title` |
| シリーズ | `series` | `Series` |
| 巻 | `seriesIndex`(文字列。`上` も入る) | `Volume`(数値だけ。`上` は入らない) |
| ネタ | (入らない) | `Neta` |
| 分類(先頭の丸括弧) | (入らない) | `Genre` |
| ファイルの同定 | パス + iノード番号 + ボリューム UUID | パスだけ |

### StackNest への渡し方

- StackNest の XML 取り込みは、**毎回新しいライブラリを作る**(既存のライブラリへは足せない)。
  XML は最初の 1 回に使い、2 回目以降の更新は StackNest のローカル API(`stacknest-cli set` / MCP)で行う想定。
- 表紙は用意しない。`Cover Image Path` に本そのもののパスを書き、表紙は StackNest の「表紙の再生成」で作る。
  (Stackroom のサムネイル置き場 `<XML と同名のフォルダ>/<ID>/thumbnail.jpg` を作れば取り込み時に写されるので、
  将来ここで作ることもできる。)
- `Book Type` はページ数を数えないので本ごとには決めない(既定 0 = 厚い本。`--book-type 1` で薄い本)。
- **StackNest の取り込みは、`Series` か `Volume` が無い本について、タイトルから独自に補う**
  (`LibraryImporter.filledBook`)。番号の無いシリーズで巻を空にしておいても、タイトルに数字があれば
  StackNest 側で巻が入る。
- 書き出した XML は、StackNest の `stackroom-import`(`swift run stackroom-import --xml … --out …`)で
  取り込めることを確かめる。終了コード 0 = 全件、1 = 一部スキップ、2 = 失敗。
  StackNest(2026-09-18 の `814c4ee`)は macOS 27 SDK ではそのままビルドできない(macOS 27 の Foundation に
  `ProgressReporter` が加わり、StackNest の同名の protocol と曖昧になる)。検証用の手元の複製では、
  `LibraryStore` に別名を足して使った(StackNest 本体には手を入れていない)。

## 実データでの測定

利用者の蔵書での測定は、手元で集計だけを見て行う(名前も集計値もここには書かない)。分かったことのうち、設計に効いたもの:

- StackNest の `stackroom-import` は、書き出した XML を全件取り込めた。取り込みのとき、`Series` か `Volume` が空の本には
  StackNest がタイトルから値を補う(上の「StackNest への渡し方」)。
- 端末内モデルは「シリーズか」をほぼ常に「はい」と答え、確からしさも判別に使えなかった。一部の組は安全装置に拒まれた。
  名前を短く整える働きはあったが、規則の改良(「公開データでの検討」)で同じところまで届いたため、今は任意の段にしている。

## 公開データでの検討

利用者の蔵書は正解が少なく、名前を外へ出せないため、**利用登録の要らない公開データ**で
規則を検討する。同人誌の正解を登録なしで得られる公開データは見つかっていないので、商業のコミックで検討し、
同人誌は手元の蔵書の集計と見直し表で確かめる。

- データ: 国立国会図書館サーチの SRU API(収益の無い個人の利用は申請不要)。NDC 726.1、2018〜2026 年の各月の
  先頭 500 件 = 52,507 件(`scripts/corpus/fetch-ndl.py`)。著者 + 「作品名 巻次」を入力、作品名を正解にする
  (`scripts/corpus/ndl-to-labeled.py`)。51,178 冊、著者 12,891 人。データはリポジトリの外に置く。
- 採点は `qoometa evaluate`: 同じ著者の本の組ごとに「同じシリーズか」を比べる適合率・再現率と、シリーズ名の一致。

### 結果(2026-09-19)

| 規則 | 適合率 | 再現率 | 名前一致 |
|---|---|---|---|
| 初版(共通部分 4 文字以上、1 段だけ) | 0.660 | 0.979 | 84.7% |
| + 1 段目(タイトル + 巻を頭でまとめる) | 0.775 | 0.947 | 95.8% |
| + 副題付きを頭の組へ入れる | 0.749 | 0.993 | 96.0% |
| + 語の切れ目なら文字数の下限なし(現行) | 0.520 | 0.996 | 96.2% |

- 短いタイトルの作品だけを取り出すと、現行の規則の再現率は 1 文字 1.000、2 文字 0.945、3 文字 1.000(初版は 3 文字で 0.879、1 文字で 0.553)。
- n はほぼ効かなくなった(n=3〜6 で適合率 0.520〜0.527、再現率は同じ)。
- **適合率の低さの大半は、正解の定義の違い。** NDL は選集・コンビニ版・外伝を副題込みの別の作品として記録する
  (「X : 〇〇編」「X 名品集」「X スペシャル」)。規則はこれらを 1 つのシリーズにまとめる。正解を「 : 」より前にしても
  適合率は 0.650 で、残りの多くも同じ系列の別冊(「Xア・ラ・カルト」と「X」など)だった。本当の誤りは、同じ著者の
  別の作品が語の切れ目まで一致する例(タイトルが同じ言い回しで始まる別作品)。
- **「どの単位を 1 つのシリーズとみなすか」は蔵書の整理の考え方で決まる**(作品か、系列か)。規則の側で決めず、
  利用者に選ばせるか、2 段(系列 / 作品)で持つかを決める必要がある。
- 同じ規則を手元の蔵書にかけると、利用者が手で登録したシリーズとの一致は、初版の規則や端末内モデルより良くなった。
  外れたのは、そのシリーズの本が蔵書に 1 冊しか無い(比べる相手が無い)場合だった。

## 未決事項

- 規則を JSON のルールセットとして外へ出す(段階ごとの規則・例外・語の一覧。コードの定数を移し、規則ごとにオン・オフして
  採点できるようにする)。
- 安全装置に拒まれた組の扱い、モデルへの問い方(端末内モデルの判定は、規則の改良でほぼ要らなくなった)。
- サークル名と作者名の置き場所(qooViewer は著者欄が 1 つ。StackNest は `Author` にまとめている)。
- StackNest が巻を補う挙動への対処(こちらで空にした巻を守りたいなら、StackNest 側の変更か、取り込み後の API 更新が要る)。
- 見直し表を「確定」の場にするか(採否をこのツールで記録するなら、編集できる画面が要る)。
- 「X2総集編」のような続編の総集編(総集編の直前の数字を収録範囲として読むので「X 総集編」の 2 巻になる)。
