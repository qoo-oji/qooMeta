# qooMeta 設計メモ

2026-09-21 に今の実装に合わせて書き直した(それまでの版は、サークル・ネタなど作り直し前の欄が前提だった。旧版は git の履歴にある)。
目的と原則は [concept.md](concept.md)、欄と書き出し先は [metadata.md](metadata.md)、ファイル名フォーマットは
[filename-format.md](filename-format.md)、規則の一覧と方針は [rules.md](rules.md)、計画と進み具合は [roadmap.md](roadmap.md)。
**規則(語の一覧・方針・読み手)の中身はここに書かない**(rules.md が本体。2 か所に書くと食い違う)。

## 目的と範囲

- 入力は**本の名前の一覧**だけ(書庫・PDF・EPUB のファイル名と、画像フォルダの本のフォルダ名)。本の中身は開かない。
  **フォルダ名は読まない**(本そのものがフォルダのときの、その名前を除く。concept.md の原則 6)。
- 出力は、qooMeta の欄(metadata.md の 2)に読んだ提案を、利用者が確かめて直したもの。書き出し先は qooViewer の保存データ JSON と、
  StackNest・ShelfRow 向けの Stackroom XML。
- **ライブラリは持たない。** 1 回きりの流れ(対象を選ぶ → 解析方法を選ぶ → 確認・編集 → 書き出す)の道具で、続きは作業ファイルに残す。

## モジュール構成

| モジュール | 中身 | ファイルに触るか |
|---|---|---|
| `QooMetaKit` | 欄(`BookMetadata`)、型の照合(`FilenameFormat`)、ルールセットの自動選択(`PresetAuto`)、中核(下の段階)、規則の読み込み・差分・カタログ(`RuleLoader`・`RuleFiles`・`RuleSchema`・`RuleCatalog`・`PresetCatalog`)、変更の索引(`ProposalIndex`)、まとめて編集(`BulkEdit`)、作業ファイル(`Workfile`)、例の実行(`Examples`)、採点(`Evaluation`) | 触らない(`scripts/ci/check-kit-purity.sh` で守る)。読み書きは `Data` まで |
| `QooMetaRules` | 同梱の既定値(`series-rules.json`・`filename-formats.json`・`examples.json`) | ― |
| `QooMetaScan` | フォルダの走査(`FolderScanner`。qooViewer が本として開けるものを拾う) | 読むだけ |
| `QooMetaExport` | 書き出し(Stackroom XML・qooViewer JSON・ComicInfo)と、書き出し先ごとの欄の対応表(`FieldMapping`)・プレビュー | 書くのは呼び出し側 |
| `QooMetaAI` | 端末内モデルでの判定(`SeriesJudge`。任意、macOS 26 以降) | ― |
| `qoometa`(CLI) | 集計だけを出す検証・一括処理。名前を含む生成物は Git の作業ツリーの外へ書く | 読み書きする |
| `App/qooMeta/` | アプリ(SwiftUI + 一覧だけ AppKit の `NSTableView`)。言葉は `Localizable.xcstrings`(英語と日本語) | 読み書きする |

本体(`QooMetaKit`)をファイルに触らせないのは、名前を外へ出さない約束(CLAUDE.md)を守る所を、走査・CLI・アプリの 3 か所に絞るため。

## 処理の流れ

```
名前 ─ 型の照合(ルールセット)→ 欄(タイトル・著者の並び・ジャンル・イベント・原作・情報、名前に書いてあれば @series @volume)
     ─ 前段(Propose.prepareOne)→ 中核の入口(CoreBook)
     ─ 単位に分ける(書き手 + ジャンル)
     ─ 中核: compare → markers → grouping → naming → volume
     ─ 確定した内容を重ねる → 提案(BookProposal・SeriesProposal)
```

### 型の照合(ファイル名の解析)

- ルールセット(JSON の鍵は `presets`)ごとに型の並びを持ち、**上から、名前全体に一致した最初の型**で読む(filename-format.md の 1・4)。
  区切り・既定の欄・型として読まない文字列(`plain`)はルールセットと型に書ける。
- どの型にも合わなかった名前は、**名前全体を仮のタイトル、書き手は空**として中核へ渡す(特別扱いしない)。一覧の絞り込み
  「フォーマットに合わない」で見つけられる。
- 名前に `@series` `@volume` で読めたシリーズ・巻数は、**利用者が確定した値と同じ扱い**で中核へ渡す(`Propose.confirming`)。
  `@volume` は巻の読み手が巻数と認めた値にだけ当たる。
- 判定は `FilenameFormats.check(_:)` の 1 つ(読み切れた / 括弧の読み残し / フォーマットに合わない、と問題の位置)。段 2 の数と、
  解析の設定の窓の名前の確かめが同じ判定を使う(画面ごとに数え方が違うと比べられない)。

### ルールセットの選び方

- 1 回の処理で、ルールセットを 1 つ選んで全冊を読むのが基本(concept.md の原則 1)。
- **「自動」**(2026-09-21): ルールセットごとに `auto`(フォルダのパスか名前に含む語、名前の先頭の語句の必須 / 例外)を書いておくと、
  本ごとに当たるルールセットを選ぶ(`PresetAutoChoice`)。当たるものが 2 つ以上なら、先頭の語句を必須にしたものを採る。
  **それでも絞れない本と、どれにも当たらない本は決めない**(道具の側で順を決めると、取り違えが見えないまま一覧に入る)。
  段 2 で「自動」を選べるのは、全冊が決まるときだけ。条件の形は filename-format.md「本ごとにルールセットを選ぶ」。
- 決まった割り当ては作業ファイルの `presets`(`defaultPreset` と、相対パスの頭か本の ID → ルールセット)に入る。
  段 3 の右クリックで選んだ本だけ別のルールセットで読み直した分も、同じ所に入る。

### 単位

中核は**単位**ごとに計算する。単位は「書き手(著者の並びの先頭。無ければ空)+ ジャンル」。方針 `differentGenre` を `keep` にすれば
書き手だけ。別の書き手の偶然の一致を最初から除くためで、書き手が空の本(雑誌・型に合わなかった名前)は 1 つの単位になる
(そのぶん大きくなるので、組み立ては冊数の 2 乗にならない作りにしてある。`ScalingTests` が守る)。

### 中核の段階

規則の JSON(`series-rules.json`)の段階と同じ順に働く。各段階の規則・語の一覧・既定値は rules.md、形式の考え方は
[rules-format-design.md](rules-format-design.md)。ここでは、段階が何を受け取り何を渡すかだけを書く。

| 段階 | 受け取る | 渡す | 主なコード |
|---|---|---|---|
| `compare` | タイトル | 比べる形(NFKC・小文字・無視する文字を除く・異体字をそろえる)と語の切れ目 | `TextForms` |
| `markers` | 比べる形 | 印を除いた比べるタイトル(版・入手経路)、総集編の印、そのまま読む語、シリーズに入れない語 | `EditionMarkers`(`WordRules`) |
| `grouping` | 単位の本 | 候補の組(と、組にならなかった理由) | `SeriesGrouper` |
| `naming` | 組の共通部分 | シリーズ名(閉じ括弧・後ろの文字を含める、末尾を落とす、最後の語を外す) | `SeriesGrouper` |
| `volume` | シリーズ名より後ろ | 巻数(表示)と巻数(ソート)、1 巻の推定、残りの文字 | `VolumeExtractor`(`ProposalFinalizer`) |

- **`markers` と `volume.readers` だけが順番のある規則表**(上の規則が取った所に、下の規則は反応しない)。ほかの段階は前の結果を
  次が受け取る工程で、並べ替えられない(rules-format-design.md「規則の順番と例外」)。
- `grouping` の組み方は大きく 2 段: 1 段目は「タイトル + 巻」の本を巻を除いた頭でまとめ(`volumeHead`)、2 段目は残りを先頭の
  共通部分でまとめる(`sharedPrefix`)。そのあとで、組を寄せる規則(副題・区切りの無い副題・「名前 + 巻」の組・自前の番号を持つ組)と、
  組にしない規則(同じ作品の版違いだけ、原作の違い …)が働く。総集編は本編と分けて扱い、置き場所は方針 `compilations` で決まる。
- `volume` は、組が決まってから本ごとに巻を読む。位置の語(上・下)や続きの本のように**組の中の文脈で数が決まるもの**は、
  組がそろってから決める。**名前から順番が分からない本に数を作らない**(2026-09-21 の方針。巻数(表示)には名前の残りを
  そのまま入れ、ソートの数は空。方針 `unnumberedVolume`)。例外は 1 巻の推定(方針 `unnumberedFirst`)だけ。
- **中核にコードで書いてよいのは、条件や読み手の種類の実装だけ。** どの語・どの数で効かせるかは JSON に置く(concept.md の原則 8)。

### 確定した内容

利用者が直した値と、型が名前から読んだシリーズ・巻数は `Confirmation`(`none` / `fields` / `series` / `notInSeries`)として中核へ渡す。
シリーズ名を確定した本は**錨**になり、規則が同じ組にした未確定の本は、その名前のシリーズに入る。「シリーズに入れない」と確定した本は、
どの組にも入らない。欄の値(タイトル・ジャンル・著者 …)を直した本は、直した値で単位と比べるタイトルが作り直される。

## 変更の索引(`ProposalIndex`)

アプリは 1 手ごとに全冊を計算し直さない。索引は本ごとの入力と単位ごとの結果を持ち、**変わった本の単位だけ**を計算し直す。

- `load`(開くとき)と `reload`(規則を替えたとき)は、名前の読み取りも単位の計算も並列。`reload` は、型の並びも `@volume` が
  頼るもの(巻の読み手・語の一覧・方針)も変わっていなければ、名前を読み直さない。取り消されたら状態は前のまま。
- `apply`(本の追加・修正・削除)は変わった提案だけを返す。`preview` は同じ計算をして状態を戻す(「選んでいない n 冊も動きます」の確かめ)。
- 状態は丸ごと写さず、変えた所だけを控えて戻す(1 冊の変更が冊数に比例しないように)。提案の全体(`snapshot`)は作り置きしない。
- 索引の結果は、一括の `proposeSync` と同じになることをテストで守る。

## 作業ファイル(`Workfile`)

- 持つのは、起点のパス・本ごとの ID(起点からの相対パス)・名前・フォルダの本か・確定した内容・ルールセットの割り当てだけ。
  **提案は持たない**(規則を変えたら計算し直せばよく、古い提案が残ると食い違う)。直していない本は修正を書かない。
- アプリの設定(規則の差分・スタンプ・書き出しの対応表・言語)とは分ける。設定は `~/Library/Application Support/qooMeta/settings.json`
  に 1 組(ライブラリ単位の設定は持たない)。読めなかった設定ファイルは消さずに隣へ残してから使い始める。
- CLI の `--in` は、`scan` が作る提案ファイルのほか、作業ファイルも読む(アプリで直したまま、一括で集計・書き出しできる)。

## アプリ

### 流れ(`FlowView`)

段のバー(1 → 2 → 3 → 4)を窓の上にいつも出し、通り過ぎた段へは戻れる。段 1・2 を通るまで一覧は出さない
(開いた瞬間に既定のルールセットを黙って当てない)。

1. **対象を選ぶ**: フォルダか、ファイルを直に複数。見つけた冊数と、種類ごとの内訳を出す。作業ファイルを開くと段 3 へ直に入る。
2. **解析方法を選ぶ**: ルールセットごとに「何件の名前を読み切れたか」を数えて並べ、「自動」も並べる。既定で選ぶのは、自動で全冊が
   決まるなら自動、そうでなければいちばん読めたもの。「解析の設定」の窓をここから開ける。
3. **確認・編集**(`WorkspaceView`): 1 冊 1 行の一覧(`BookTable`。`NSTableView`)、上に絞り込みの帯(ジャンル → 著者、本の状態、検索)、
   右に詳細(`DetailView`)。
   - 一覧: 見出しで並べ替え、列の並び・幅・表示は覚える。2 回押しでそのセルを直す(ファイル名と巻数(ソート)は読むだけ)。
     直した欄は色を変える。**どのフォーマットにも合わなかった本は灰色**。
   - **右クリックで、選んだ本を別のルールセットで読み直す**(割り当ては本ごとに作業ファイルへ入る)。
   - 詳細: 欄の編集(複数選択ならまとめて。揃わない欄は「複数の値」)、欄ごとに「提案に戻す」、スタンプ、シリーズの操作
     (1 つにする・巻を決める・確定する・外す・巻を消す・提案に戻す・連番を振る)、名前のどこがどの欄になったか(一致した型、
     合わなければいちばん近い型と外れた位置)。
   - 選んでいない本まで動くシリーズの操作は、`preview` の数を見せて確かめる。直したことはすべて取り消せる(⌘Z)。
   - 段 2 へ戻ってルールセットを替えても一覧は作り直さない(割り当てだけ替えて読み直す。直した内容を消さないため)。
4. **書き出す**(`ExportView`): 書き出し先を選び、対応表(欄 → 行き先)を変えると、落ちる冊数・先頭だけになる冊数がその場で変わる。
   書いた先を「Finder で表示」まで出す。

### 窓

| 窓 | 開き方 | 中身 |
|---|---|---|
| 一覧の窓 | 起動 | 上の流れ |
| **解析の設定**(ファイル名の解析。`FileNameRulesView`) | 段 2 のボタン、メニュー(⌥⌘1) | `filename-formats.json` の担当分: ルールセットの一覧・型の並び・区切り・既定の欄・`plain`・`auto`、名前の確かめ(保存してある版と下書きで読み比べ、問題の位置を強調)、差分(JSON) |
| **抽出の設定**(シリーズと巻数の抽出。`SeriesRulesView`) | 段 3 のツールバー、メニュー(⌥⌘2) | `series-rules.json` の担当分: 「やりたいこと」(困りごとから設定へ)、方針、語の規則、巻の読み手、組み方と名前、語の一覧、差分(JSON) |
| 環境設定 | ⌘, | 言語(システムに従う / 英語 / 日本語)、最後の窓を閉じたら終わるか |

- 窓を段で分けたのは、当たる処理の段が違うから(2026-09-21、利用者の指摘)。各窓の上に、何から何を作る段か・もとの JSON の名前を帯で出す。
- 窓が持つのは**既定値との差分だけ**。操作はすべて `RuleChanges` を通し、1 か所変えるたびに組み立て直す(誤りがあれば変えずに理由を出す)。
  変えた内容は、どの段にいても開いている一覧へ届く(`FlowView` が規則のハッシュを見て、少し待ってから読み直す)。
- 画面では「プリセット」と言わず「ルールセット」と呼ぶ(利用者が足したものも呼べるように)。コードの識別子と JSON の鍵は `presets` のまま。

## 書き出し

- **読み方は 1 つ、書き出し先ごとの違いは対応表で振り分ける**(`FieldMapping`。既定と、利用者が変えた表は設定に残る)。
  行き先に出すのは、そのアプリの取り込みが実際に読む欄だけ(`ExportTarget.slots`。読まない欄へ渡すと、成功したのに値だけが消える)。
  既定の表は metadata.md「書き出し先ごとの欄の対応」。
- 書き出す前に `Exporter.preview` が、欄ごとの行き先・値があるのに落ちる冊数・著者が先頭だけになる冊数を数える(名前は含まない)。
  CLI の `export` も書く前にこれを出す。
- qooViewer の JSON は `formatVersion: 4` の `metadata`(bookID・author・title・series・seriesIndex)。本の同定は パス + iノード番号 +
  ボリューム UUID。Stackroom XML は、StackNest・ShelfRow の取り込みのコードで読めることを確かめてある(handoff.md)。
  StackNest の XML 取り込みは毎回新しいライブラリを作る。`Series` か `Volume` が空の本には、StackNest がタイトルから値を補う。
- ComicInfo の書き出し(`Exporter.comicInfoXML`)はコードにあるが、アプリからも CLI からも使っていない。

## CLI(`qoometa`)

`scan`(走査 + 提案 + 集計)・`stats`・`formats`・`export`・`bench`・`evaluate`・`rules test|validate|show`・`judge`(端末内モデル。任意)・
`report` / `series-list`(名前を含むので、手元で開く用)。**標準出力には名前を出さない**。名前を含む生成物は
`~/Library/Application Support/qooMeta-dev/` へ書き、Git の作業ツリーの中へは書かない。`--rules` で規則の差分を、`--presets` で
ルールセットの割り当てを渡せる。使い方は `qoometa` を引数なしで。

## 端末内モデルの判定(任意)

規則の組を 1 つずつ端末内モデル(Apple Intelligence)に渡し、シリーズか・名前はどこまでか・外す本はどれかを答えさせる
(`SeriesJudge`、CLI の `judge`。通信はしない)。手元の蔵書では「シリーズか」にほぼ常に「はい」と答え、確からしさも判別に使えず、
規則の改良で同じところまで届いたので、**今は任意の段**でアプリからは使っていない。判定は確定した内容として渡す。

## 確かめ方

- `swift test`(合成した名前だけ)、`qoometa rules test`(例のファイル。架空の名前だけ)、`bash scripts/ci/check-all.sh`。
- 手元の蔵書では、**結果の指紋**(`qoometa scan` の最後の行)と集計だけを見る。基準値と変わった理由は handoff.md。
- 公開データ(国立国会図書館の書誌)での採点は `qoometa evaluate`(データはリポジトリの外。取り方は `scripts/corpus/`)。
- 速さとメモリは `qoometa bench --synthetic N`(合成した名前。`--no-authors` は全冊が 1 つの単位になる、いちばん重い形)。

## 未決事項

- **StackNest が空の巻を補う挙動**: こちらで空にした巻数も、StackNest の取り込みがタイトルから補う。空のまま守りたいなら、
  StackNest 側の変更か、取り込み後に API で直すことが要る。
- **qooViewer の巻数(ソート)**: qooViewer の JSON には数の欄が無く、既定の対応表では落ちる。qooViewer 側に欄を足すかどうか
  (metadata.md の表)。
- **フォーマットの取り込み・書き出し**(StackNest のテンプレート・ShelfRow のフォーマット・qooViewer のファイル名フォーマット):
  まだ作っていない(roadmap.md の段階 12)。
- **端末内モデルの判定の扱い**: 安全装置に拒まれた組の扱いと問い方。規則の改良でほぼ要らなくなったので、残すか外すか。
- **書き手の読めない蔵書の重さ**: 全冊が 1 つの単位のとき、1 冊の変更がその単位の計算し直しになる(2 万冊で 0.35 秒)。
  単位の中の組み立てを差分にするのは、まだ。
- 「X2総集編」のような続編の総集編(総集編の直前の数字を収録範囲として読むので「X 総集編」の 2 巻になる)。
