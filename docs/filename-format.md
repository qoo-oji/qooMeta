# ファイル名フォーマット(提案)

2026-09-19。**名前のどの部分を何の欄とみなすか(捨てるかを含む)は、利用者がファイル名フォーマットで決める。** 雑多な情報(`[DL版]`
など)の扱いも、フォーマットに `@ignore` と書けば捨てる、`@keywordA` と書けばキーワード A に入る、というだけのことになる。
qooMeta 側で「雑多な情報」を別に扱う仕組みは作らない。

**土台は、ターゲットの 3 つのアプリ(qooViewer・StackNest・ShelfRow)のフォーマットの書き方**で、これは要件(型を持ち運べるように
同じ書き方にする)。qooLibrary はターゲットではなく参考で、書き方も語もコードも持ってこない(concept.md「ターゲットと参考」)。
照合の処理は、下の 1 の書き方だけを読むものを qooMeta で書く(写してあった `Sources/QooFormat` は捨てる)。

## 1. 書き方

### ターゲットの 3 つのアプリに共通する部分(要件)

| 項目 | 内容 | どのアプリにあるか |
|---|---|---|
| 予約語で欄を指す | `[@author] @title (@source)` のように、欄の位置を予約語で書く。予約語以外の文字はそのまま照合する | 3 つとも |
| フォーマットの並び | 上から照合し、名前全体に一致した最初のものを採る | qooViewer(並び)、StackNest(名前付きで複数) |
| 括弧 | `[ ]` と `( )` の中に予約語を書く。括弧の中の括弧(`[@author (@author)]`)も書ける | 3 つとも(入れ子は ShelfRow・qooViewer) |
| 空白 | フォーマットの空白は「0 文字以上の空白」 | 3 つとも |
| 読まない部分 | `@ignore`。何度でも書ける | qooViewer |

### qooMeta で足すもの

ターゲットの書き方に無く、qooMeta の役目(合わなかった名前を見つけて型を直す)のために足すもの。

| 足すもの | 理由 |
|---|---|
| 最も近いフォーマットを示す | どの型にも合わなかった名前を直すとき、どこで外れたかを見せるため |
| 全角と半角の括弧(`()` と `（）`、`[]` と `［］`)を同じとみなす | 書き手の入力の揺れで、意味は同じ。空白と同じ扱い |

照合の細かい決まり(qooMeta の実装。2026-09-19):

- 括弧の中に書いた欄の値には、その括弧の対の文字(全角・半角とも)を含めない(`(@source)` の値に `(` `)` は入らない)。
  括弧の外の欄(`@title`)には何でも入る。
- 欄は長く取るほうを先に試す。区切りの文字が何度も現れる名前は、最後のもので分ける(`@title - @author` で `A - B - C` なら
  タイトル `A - B`)。
- 欄と欄のあいだには、空白のほかの文字が要る(`@title @author` は書けない。どこで分けるかが決まらない)。型には `@title` が要る。
- 並びの欄(著者・ジャンル・関連・キーワード)の値は区切り(既定は `,` `，` `、`)で分ける。全角のカンマは `,` の幅の違いとして同じに扱う。
- 最も近い型は、型の頭から満たした部品がいちばん多いもの(同じなら、読めた文字が多いもの、上のもの)。どの型も最初の部品から
  外れる名前(括弧の無い名前など)には、近い型を示さない。

足さないもの: `「」` `【】` を括弧として特別に扱うこと、` - ` `_` `＿` を区切りとして特別に扱うこと(これまでの案にあった)。`「」` は本では
タイトルの一部であることが多く、構造として読むと題名を壊す(先方でこれを構造に使っているのは動画のサブタイトル)。`【】` や ` - ` を
使う命名の利用者は、予約語以外の文字はそのまま照合されるので、`【@ignore】 @title` のように型に書けば足りる。

**タイトルからシリーズ名と巻数を取り出すのに、`@series` `@volume` をフォーマットに書くやり方(StackNest・qooLibrary)は採らない。**
シリーズと巻は名前の形として定式化できない(同じ形でも巻だったり題名の一部だったりする)。だから qooMeta は、それを複雑な条件を書ける
規則の JSON で扱っている(3)。フォーマットは欄の位置を読むところまで。`@season` `@episode` `@subtitle` `@actor` など動画向けの語も取り入れない。

## 2. 予約語

**StackNest・ShelfRow の予約語を土台に**し、足りない分を補う。

| 予約語 | 欄 | 出どころ | 備考 |
|---|---|---|---|
| `@title` | タイトル | StackNest・ShelfRow | |
| `@author` | 著者 | StackNest・ShelfRow | 何度でも書ける。値は区切りで分けて、書いた順・読んだ順に並べる(下) |
| `@genre` | ジャンル(本の種類) | StackNest・ShelfRow | ほかの欄と同じ自由な文字列 |
| `@source` | 関連(二次創作の元作品) | StackNest・ShelfRow の `@relation` | 綴りだけ変える(下) |
| `@keywordA` `@keywordB` | キーワード A・B | StackNest・ShelfRow | |
| `@keywordC` | キーワード C | StackNest | |
| `@type` | 種類 | StackNest・ShelfRow | ShelfRow は読んで使う(StackNest は取り込みで捨てる) |
| `@ignore` | (捨てる) | 補う(qooViewer) | 何度でも書ける |

- StackNest の `@series` `@volume` は置かない。シリーズと巻はタイトルから規則の JSON で導く(3)。StackNest のテンプレートを取り込むときは、
  その部分を `@title` へまとめる(StackNest 自身も取り込みで捨てている)。
- `@relation` は `@source` と綴る(2026-09-19 決定)。中身は二次創作の元作品(英語圏では source material)。`@original` は、同人誌で
  この欄に「オリジナル」(二次創作ではない)と書かれるものと紛れ、`@parody` は日本では二次創作と違う印象を持たれるため採らない。
  StackNest・ShelfRow のテンプレートを取り込むときは `@relation` を `@source` に読み替え、書き出すときは戻す。
- メモは予約語にしない(利用者が手で書く欄。名前の中の付記はキーワードで足りる)。
- 同じ予約語を 1 つのフォーマットに 2 度書けるのは `@author` と `@ignore` だけ。
- **著者の区切り**: `[@author (@author)]` の括弧と、`,` `、`(2026-09-19 決定)。設定で足せる。`×` `&` `・` は 1 つの名義(ユニット名・
  サークル名)の中にも現れ、取り違えると著者の先頭(中核の比べる単位)が壊れるので、既定には入れない(同梱の型と同じ基準。5)。
  `[作画×原作]` の形が多い利用者は設定で `×` を足す。分けなくても、1 つの名義として一貫して同じ単位になるので、シリーズは崩れない。
- これまでの `@circle`・`@event` は撤去する(サークル名は `@author` の先頭、イベント名は `@ignore` か、利用者が選んだキーワードへ)。

## 3. シリーズと巻

**タイトルからシリーズ名と巻数を取り出す処理は qooMeta の中核**で、ほかのアプリ(qooLibrary・qooViewer・StackNest)のやり方に寄せない。
シリーズと巻は名前の形として定式化できない(同じ形でも巻だったり題名の一部だったりする)から、qooMeta は複雑な条件を書ける規則の JSON
(`Sources/QooMetaRules/Resources/series-rules.json`、利用者の変更は差分で重ねる)と、ほかの本と見比べる仕組みで扱っている。

- フォーマットは欄の位置を読むところまで。シリーズと巻は、フォーマットで読んだタイトルと著者の並びを入力に、今の規則と仕組みで導く。
- 見直しで変わるのは入力の欄の名前(サークル → 著者の並びの先頭 …)だけで、規則の中身と仕組みは変えない。
- qooViewer の除外文字列・巻数フォーマットは、フォーマットの取り込みの対象にしない(用途は近いが、規則に写すと中核の考え方が崩れる)。

## 4. 設定の持ち方・プリセット・持ち運び

- **qooMeta にはライブラリが無い**(開いたファイルの一覧からメタデータを作って書き出すだけ)。だから、フォーマットの並びと規則の差分は
  **アプリの設定**として 1 組持つ(qooViewer と同じ)。StackNest のライブラリごとのテンプレートや qooLibrary の
  ライブラリ単位の設定には合わせない。命名の違う本が混ざっていても、並びの上から名前全体に一致した最初の型で読むので、並び 1 つで足りる。
- 同梱するのは型の並び 1 つ(5)。利用者はそれを複製し、並べ替え・書き足しをする(同梱のものは書き換えない)。
- 取り込み: qooViewer の JSON のファイル名フォーマット、StackNest のテンプレート、ShelfRow のフォーマット
  文字列を読み込めるようにする(予約語の綴りが同じなので、ほぼそのまま移せる)。除外文字列・巻数フォーマットは取り込まない(3)。
- 書き出し: qooMeta で詰めたフォーマットを、各アプリの形式でも書き出せるようにする(各アプリの予約語に無い欄は `@ignore` にする)。

## 5. 同梱するプリセット

同梱するのは、**命名の違う本が混ざった蔵書をそのまま読む、型の並び 1 つ**。本の種類ごとの組(コミック用・同人誌用 …)には分けない
(原則 1。種類ごとの組は、ライブラリを種類で分ける qooLibrary の考え方で、qooMeta にはライブラリが無い)。

### 出発点はターゲットの既定

qooViewer の既定のフォーマットは 12 通り(`Models/MetadataFormatRule.swift`)。先頭の丸括弧・著者の後ろの丸括弧・末尾の丸括弧・
末尾の角括弧の有無の組み合わせを、具体的なものから順に並べている。読むのは著者とタイトルだけで、ほかの位置は `@ignore`:

```
(@ignore) [@author (@ignore)] @title (@ignore) [@ignore]
(@ignore) [@author (@ignore)] @title (@ignore)
(@ignore) [@author (@ignore)] @title
  … ([@author] だけの 3 通り、先頭の丸括弧が無い 6 通り)
[@author] @title
```

ShelfRow の既定は `[@author] @title`、合わないときの固定の読み方は `(ジャンル)[作者]タイトル`(末尾の角括弧は捨て、末尾の丸括弧は読まない)。
ターゲットが前提にしている名前の形は、この 12 通りに収まる。qooMeta の同梱の並びは、**この形を土台に、`@ignore` の位置へ qooMeta の欄を
割り当てたもの**にする。

### 位置ごとの割り当て

| 位置 | 既定の欄 | 理由 |
|---|---|---|
| 先頭の丸括弧 | `@genre` | ShelfRow の固定の読み方がジャンルとして読む。StackNest でも利用者は本の種別に使っている。イベント名などが入る名前もあるが、形では見分けられないので、値の列で気づいてまとめて直す(roadmap.md のジャンルについての決定) |
| 角括弧の中の丸括弧 | `@author`(2 つ目以降) | 名義が複数ある(metadata.md の 2)。StackNest は著者が複数値 |
| 末尾の丸括弧 | `@source` | StackNest・ShelfRow に関連の欄があり、中核も方針 `differentRelation` で使う |
| 末尾の角括弧 | `@ignore` | 付記(入手経路など)。ShelfRow にキーワード C が無く、キーワード A・B は利用者の分類と混ざる。要る利用者は複製して変える |

### 参考(qooLibrary のプリセット)を吟味した結果

qooLibrary のプリセットは、実際の蔵書と突き合わせて直されてきたもので、命名についての知識が入っている。そのまま使わず、1 つずつ
qooMeta に要るかを見た。

| qooLibrary のプリセットにあること | qooMeta での扱い |
|---|---|
| 名前の形は「先頭の丸括弧 / 角括弧(中に丸括弧)/ タイトル / 末尾の丸括弧 / 末尾の角括弧」の有無の組み合わせ | **同じ結論**。ターゲットの qooViewer の 12 通りと同じ形で、裏づけになる |
| 末尾の丸括弧が無く、末尾の角括弧だけがある形(`… @title [付記]`)。qooViewer の 12 通りには無い | **取り入れる**。理由は下の「同梱の並び」(qooMeta ではタイトルに付記を残せない) |
| 先頭の丸括弧は、本の種別のこともイベント名のこともある。語の一覧で見分けないと、取り違えが 1 割を超える(先方の実測) | **知識だけ取り入れる**。語の一覧は持たない(決定済み)。取り違えが珍しくないと分かっているので、値の列で見つけてまとめて直す流れを、骨組みの画面(roadmap.md の段階 5)で最初から確かめる |
| `@title` だけの型は入れない(何にでも一致して、直すべき名前が「読めた」ことになって埋もれる。先方の実測でも裏づけ) | **取り入れる**。qooMeta でも、合わなかった名前は型を直す入口なので、埋もれさせない |
| 具体的な型を上、緩い型を下に並べる | **取り入れる**(qooViewer の既定も同じ並べ方) |
| 本の種類ごとにプリセットを分ける(4 組)。フォルダ名の型。種類ごとの巻の表記の組 | **取り入れない**。ライブラリを種類で分ける前提のもの。qooMeta は並び 1 つ、フォルダ名は読まない、巻は中核の規則 |
| サークルと著者を別の欄にする(`@studio` `@author`)。イベントの欄(`@event`)。キーワードの欄が 1 つ | **取り入れない**。欄はターゲットの和集合(metadata.md の 2) |
| 動画のプリセット | **取り入れない**(本ではない) |

### 選ぶ基準

型を同梱するかどうかは、一致する冊数ではなく、**取り違えたときに何が壊れるか**で決める。同梱の並びは利用者が何も考えずに最初に使うもの
なので、

- 形から意味がほぼ決まる型、または取り違えても**タイトルと著者は正しく**、ずれるのが脇の欄(ジャンル・関連)だけの型は入れる。
  脇の欄のずれは値の列で目に見え、まとめて直せる。
- 取り違えると**タイトルや著者そのものが壊れる**型は入れない。壊れた著者は中核の比べる単位になり、静かにシリーズを崩す。
  そういう名前は「合わなかった名前」に出るほうがよい(利用者が自分の命名に合わせて型を足す)。

### 同梱の並び

```
(@genre) [@author (@author)] @title (@source) [@ignore]
(@genre) [@author (@author)] @title (@source)
(@genre) [@author (@author)] @title [@ignore]
(@genre) [@author (@author)] @title
(@genre) [@author] @title (@source) [@ignore]
(@genre) [@author] @title (@source)
(@genre) [@author] @title [@ignore]
(@genre) [@author] @title
[@author (@author)] @title (@source) [@ignore]
  … (先頭の丸括弧が無い 8 通り。同じ順)
```

qooViewer の 12 通りに、**末尾が角括弧だけの形**(`… @title [@ignore]`)の 4 通りを足した 16 通り。qooViewer に無いのは、著者とタイトルしか
使わない閲覧アプリでは付記がタイトルに残っても困らないから。qooMeta のタイトルは書き出し(EPUB・PDF の題名)と中核の入力になるので、
付記を残さない。取り違え(題名が本当に `[…]` で終わる本)は稀で、起きてもタイトルの末尾が欠けるだけで、一覧で見える。

入れないもの:

- `@title - @author`(作者が末尾に ` - ` で付く形。これまでの案では足すとしていた)。括弧の無い名前で ` - ` を含むものすべてに一致するので、
  「題名 - 副題」の本の副題を著者に取り違える。タイトルも著者も壊れ、しかも「読めた」ことになって埋もれる。この命名を使う利用者が
  自分で足す型(区切りが複数あるときは最後のもので分ける、という読み方だけは用意する)。
- `@title [@author]`(作者が末尾の角括弧)。末尾の角括弧が作者か付記かは形で決まらず、取り違えると著者が壊れる。
- `@title`(タイトルだけ)。何にでも一致して、直すべき名前が埋もれる。

**残る弱点(利用者に見える形にして、設定で逃がす)**: 末尾の丸括弧を `@source` と読むのは二次創作の本の慣習で、商業の本では末尾の丸括弧が
別の意味(レーベル・版など)のことがある。取り違えてもタイトルと著者は正しいが、中核は関連が違う本を分ける(方針 `differentRelation`)ので、
シリーズが割れうる。ジャンルと同じ扱いにする: 値の列で見つけてまとめて直せ、方針は設定で `keep` にできる。商業の本の多いフォルダでの
集計(roadmap.md の段階 1)で、この取り違えがどのくらい起きるかを先に測る。

集計(roadmap.md の段階 4)は採否を決めるためではなく、確かめるために取る: 型ごとの一致冊数と、どの型にも合わなかった冊数。合わなかった
冊数が多ければ、その名前の形(文字種に置き換えたもの)を見て、基準に照らして型を足すかを考える。

## 6. これまでの qooMeta から変わること

| これまで | これから |
|---|---|
| 予約語の対応表が意味とずれていた(`@genre` → 照合の処理の `@mediatype`、`@relation` → `@genre` …) | 予約語 = qooMeta の欄。照合の処理の内部の名前は利用者に見せない |
| `@ignore` を外に出していなかった | 使える(シリーズと巻は予約語にせず、規則で導く) |
| 同人誌の 1 組と「括弧の位置だけで読む」予備 | 利用者の並べた型。どれにも合わなければ「合わなかった名前」として直す対象に出す |
| 版・入手経路の印を、欄とは別の仕組みで見分けていた | 名前の中の印をどの欄に入れるか(捨てるか)はフォーマットで決める(`[@ignore]`・`[@keywordA]` …)。タイトルの中に残る印を比べるときに除くのは、今の規則のまま(3) |
| フォルダ名は書き手の代わりにだけ使っていた | フォルダ名は読まない(2026-09-19 決定。3 つのアプリはどれもフォルダ名を読まない。フォルダ名の型は qooLibrary 固有) |

## 7. 決めてほしいこと
