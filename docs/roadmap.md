## 何を移し、何を作り直すか

| 移す(ロジックと規則の中身を変えない) | 作り直す |
|---|---|
| 巻の読み取り(VolumeExtractor)・シリーズの組み立て(SeriesGrouper)・文字の正規化(TextForms) | 名前を欄に分ける部分(NameParser・QooLibraryNameParser) |
| **比べるタイトルを作る処理**(版・入手経路の印を除く EditionMarkers の `split`、総集編の語順の直し)。捨てるのは版・入手経路の「欄」だけ | 欄の持ち方(サークル・版・入手元の欄をやめる。イベントは新しい欄として持つ) |
| 規則の JSON・読み込み・検証・カタログ(第 2 版の形式) | 書き出し・作業ファイル・CLI・アプリの画面 |
| 例のファイル(examples.json)と結果の指紋 | 型の照合(qooMeta で書く。qooLibrary から写した `Sources/QooFormat` は捨てる) |
| 変更の索引・まとめて編集・確定した内容の考え方 | |

**qooLibrary のコードは持ってこない(2026-09-19 決定)。** qooLibrary は参考情報として参照するだけのもの。写してあった `Sources/QooFormat` は
捨て、型の照合は新しい書き方(filename-format.md の 1・2)だけを読む小さなものを qooMeta で書く。QooFormat は、段階 2 の「指紋が変わらない」
確認に今の前段が要るあいだだけ残し、前段を替える段階 6 で消す。移す側で QooFormat に依っているのは、規則の読み込みの 1 か所
(`RuleLoader.swift` の、正規表現の危険な形の検査 `RegexSafety.staticFindings`)だけで、これも qooMeta で書き直す(本当の守りは照合の
時間の上限で、こちらは qooMeta のコードにある)。

## 中核の入口

中核が読むのは「タイトルと著者の先頭」だけではない。今のコードが実際に読んでいるものを、入口の型として固定する。

| 入力 | 今の出どころ | 作り直した後の出どころ |
|---|---|---|
| 本の ID | 走査の起点からの相対パス | 同じ |
| 比べるタイトル | 読んだタイトルから印を除き、総集編の語順を直したもの | 同じ処理を `@title` の値にかける |
| 書き手のキー | サークル。無ければいちばん近いフォルダ名 | 著者の並びの先頭。無ければ空(書き手が空の本は 1 つの単位になる。下) |
| ジャンル | 本の種別(語の一覧に一致したものだけ) | `@genre` の値。**比べる単位に入れ、ジャンルが違えば分ける**(2026-09-19 決定) |
| 原作 | 末尾の丸括弧 | `@source` の値。方針 `differentRelation` で使う |
| 確定した内容 | `Confirmation` | 同じ考え方(欄は新しい欄) |

**ジャンルについての決定(2026-09-19)**: 単位は今と同じ「書き手 + ジャンル」。語の一覧を持たないので、型によっては `@genre` にイベント名などが
入り、シリーズが割れる。これは仕組みで防がない。値の列と一覧でジャンルの欄を見れば利用者が気づくので、アプリは**まとめて直す手段**
(全選択を含む複数選択 + 1 回の入力で、選んだ全冊の任意の欄を書き換える)を用意し、直したらシリーズを組み直す。
原作(`@source`)の取り違えも同じ扱いにする(方針 `differentRelation`)。
**ジャンルを見ない(単位を書き手だけにする)ことも利用者が設定で選べる。** 仕組みは今の規則の方針 `differentGenre`(`split` / `keep`、
既定は `split`)をそのまま移し、アプリの設定の画面から切り替えられるようにする(規則の差分として持つ)。切り替えたら全体を組み直し、
適用前のプレビューで変わる本を見せる。

**書き手が空の本・どの型にも合わなかった名前(2026-09-19 決定)**: 特別扱いしない。合わなかった名前は「名前全体 = 仮のタイトル、書き手は空」
として中核へ渡し(仮と分かる印を付け、型の編集の窓の「合わなかった名前」にも出し続ける)、書き手が空の本は 1 つの単位としてほかと同じ規則で
組む。作者の違う本が偶然の一致で組になることはあり得るが、**道具の側で偏りをかけない**(書き手が空の単位だけ規則を弱める、といった
ことをしない)。一覧をタイトルやシリーズで並べれば利用者が見つけられ、シリーズから外す操作で直せる。中核に例外を足さないので、
「中核の中身を変えない」もそのまま守れる。単位が大きくなる分の速さは段階 6 で測る。

## 決めたことの控え

### 総集編の扱い(2026-09-20 に利用者が決めた)

決まったこと:

- **巻数を 2 つ持つ**: 巻数(ソート用。`Double?`、シリーズの中の位置)と巻数(表示用。`String`、名前のとおりの表記)。
  欄は `BookMetadata.volumeSort` と `.volume`(metadata.md「書き出し先ごとのシリーズと巻」)。
- **総集編は、シリーズに含める / 含めないをアプリの画面で切り替える。** 含めるときは、任意の**オフセット**を足した数を巻数(ソート用)にする
  (オフセット 100、「総集編2」なら 102.0)。含めないときは別のシリーズ(「X 総集編」。今の方針 `compilations` の `ownSeries`)。
- **書き出し**: StackNest へは巻数(ソート用)をそのまま巻数の欄へ、巻数(表示用)は空いている欄へ。ShelfRow へは巻数(ソート用)を捨て、
  巻数(表示用)を空いている欄へ。qooViewer は両方を専用の欄で持てるようにアプリ側を拡張する想定。

そのほか(2026-09-20 に決めた):

- 切り替えとオフセットは、規則ファイルの方針ではなく**アプリの画面で設定する**。
- **番号の無い総集編**(表記が「総集編」だけ)は、オフセット + 1(総集編 1 と同じ扱い)。
- **番外編**も同じくオフセットで扱う。オフセットは 1 つで、総集編と番外編で分けない。
- **特装版・フルカラー版などの版違いは巻にしない。** 中身が同じ本なので、同じ本の重複として扱う(今の中核と同じ扱いを続ける。
  `EditionMarkers` で印を除いた比べるタイトルが同じ本だけの組は、シリーズにしない)。
- **番号の無い本**は、巻数(ソート用)を 1.0(これまでの推定と同じ)、巻数(表示用)は空のまま。

- **重複(版違い)は、一覧で印を付ける(または強調する)だけ**にする。まとめて 1 行にはしない。
- **「フルカラー総集編」は、総集編とも重複とも見なさない**(2026-09-20、利用者の指摘)。独立した 1 冊として扱う。
  - いまの中核はこうなっていない: `Compilation.keywordWords`(`総集編` `総集篇`)がタイトルの中に見つかれば総集編とみなし、
    `SeriesGrouper.compilation` は「X フルカラー総集編」の本編の候補として「X フルカラー」と「X」を挙げる。
  - **直した(2026-09-20、段階 7 の最初)**: 総集編の語のすぐ前に版の語が区切り無しで続く形は、総集編にしない。版の印としても
    外さない(タイトルの一部として残す)。判定は規則の JSON で効かせる(条件 `grouping.compilation.conditions.reject-edition-prefix`、
    語は一覧 `editionPrefixWords`。条件の種類だけがコード。concept.md の原則 8)。括弧や空白を挟む形
    (「X【フルカラー版】総集編」)は、これまでどおり版の印として外して総集編にする。
  - 手元の蔵書での違いは小さかった(handoff.md「確かめ方と基準値」)。指紋は変わる。
