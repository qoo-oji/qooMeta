## 何を移し、何を作り直すか

| 移す(ロジックと規則の中身を変えない) | 作り直す |
|---|---|
| 巻の読み取り(VolumeExtractor)・シリーズの組み立て(SeriesGrouper)・文字の正規化(TextForms) | 名前を欄に分ける部分(NameParser・QooLibraryNameParser) |
| **比べるタイトルを作る処理**(版・入手経路の印を除く EditionMarkers の `split`、総集編の語順の直し)。捨てるのは版・入手経路の「欄」だけ | 欄の持ち方(サークル・イベント・版・入手元の欄をやめる) |
| 規則の JSON・読み込み・検証・カタログ(第 2 版の形式) | 書き出し・作業ファイル・CLI・アプリの画面 |
| 例のファイル(examples.json)と結果の指紋 | 型の照合(qooMeta で書く。qooLibrary から写した `Sources/QooFormat` は捨てる) |
| 変更の索引・まとめて編集・確定した内容の考え方 | |

**qooLibrary のコードは持ってこない(2026-09-19 決定)。** qooLibrary は参考情報として参照するだけのもの。写してあった `Sources/QooFormat` は
捨て、型の照合は新しい書き方(filename-format.md の 1・2)だけを読む小さなものを qooMeta で書く。QooFormat は、段階 2 の「指紋が変わらない」
確認に今の前段が要るあいだだけ残し、前段を替える段階 6 で消す。移す側で QooFormat に依っているのは、規則の読み込みの 1 か所
(`RuleLoader.swift` の、正規表現の危険な形の検査 `RegexSafety.staticFindings`)だけで、これも qooMeta で書き直す(本当の守りは照合の
時間の上限で、こちらは qooMeta のコードにある)。

## 中核の入口

中核が読むのは「タイトルと著者の先頭」だけではない。今のコードが実際に読んでいるものを、入口の型として固定する。

| 入力 | 今の出どころ | 作り直した後の出どころ |
|---|---|---|
| 本の ID | 走査の起点からの相対パス | 同じ |
| 比べるタイトル | 読んだタイトルから印を除き、総集編の語順を直したもの | 同じ処理を `@title` の値にかける |
| 書き手のキー | サークル。無ければいちばん近いフォルダ名 | 著者の並びの先頭。無ければ空(書き手が空の本は 1 つの単位になる。下) |
| ジャンル | 本の種別(語の一覧に一致したものだけ) | `@genre` の値(並びなら先頭)。**比べる単位に入れ、ジャンルが違えば分ける**(2026-09-19 決定) |
| 関連 | 末尾の丸括弧 | `@source` の値。方針 `differentRelation` で使う |
| 確定した内容 | `Confirmation` | 同じ考え方(欄は新しい欄) |

**ジャンルについての決定(2026-09-19)**: 単位は今と同じ「書き手 + ジャンル」。語の一覧を持たないので、型によっては `@genre` にイベント名などが
入り、シリーズが割れる。これは仕組みで防がない。値の列と一覧でジャンルの欄を見れば利用者が気づくので、アプリは**まとめて直す手段**
(全選択を含む複数選択 + 1 回の入力で、選んだ全冊の任意の欄を書き換える)を用意し、直したらシリーズを組み直す。
関連(`@source`)の取り違えも同じ扱いにする(方針 `differentRelation`)。
**ジャンルを見ない(単位を書き手だけにする)ことも利用者が設定で選べる。** 仕組みは今の規則の方針 `differentGenre`(`split` / `keep`、
既定は `split`)をそのまま移し、アプリの設定の画面から切り替えられるようにする(規則の差分として持つ)。切り替えたら全体を組み直し、
適用前のプレビューで変わる本を見せる。

**書き手が空の本・どの型にも合わなかった名前(2026-09-19 決定)**: 特別扱いしない。合わなかった名前は「名前全体 = 仮のタイトル、書き手は空」
として中核へ渡し(仮と分かる印を付け、型の編集の窓の「合わなかった名前」にも出し続ける)、書き手が空の本は 1 つの単位としてほかと同じ規則で
組む。作者の違う本が偶然の一致で組になることはあり得るが、**道具の側で偏りをかけない**(書き手が空の単位だけ規則を弱める、といった
ことをしない)。一覧をタイトルやシリーズで並べれば利用者が見つけられ、シリーズから外す操作で直せる。中核に例外を足さないので、
「中核の中身を変えない」もそのまま守れる。単位が大きくなる分の速さは段階 6 で測る。

## 段階

各段階は「終わりの条件」が通るまで次へ進まない。

0. **片付け**(済み。2026-09-19): 未コミットの試作(`App/`・`QooMetaPreview` …)を捨て、`CLAUDE.md` の冒頭を直した。消したあと
   `swift build`・`swift test`(74 件)・`qoometa rules test`(84 件)が通ることを確かめた。
1. **基準を取る**(済み。2026-09-19。値は handoff.md): 今の実装のまま、手元の蔵書の指紋(`bf1bb7c0…`)と、公開データの適合率・再現率を取り直す。併せて、商業コミックの多い
   フォルダでも集計(冊数・候補の組数・シリーズに入らなかった冊数・末尾の丸括弧を持つ冊数と、その値の違いで割れた組の数)を取る(原則 1 の弱点を最後ではなく最初に知るため)。
   - 終わりの条件: 基準値を handoff.md に記録(名前は書かない)。
2. **中核を入口の後ろへ切り出す**(済み。2026-09-19)(今のコードの中で): 上の表の入口の型を作り、今の読み取り(NameParser など)の結果をその型に詰めて
   中核へ渡す形に直す。前段はまだ替えない。入口と中核の中の語は qooMeta の欄の語にする(qooLibrary 由来の `mediaType` `Vocabulary` などを
   ジャンル・関連へ。concept.md「ターゲットと参考」)。
   - 終わりの条件: 指紋が段階 1 と **1 文字も変わらない**。`swift test` と `qoometa rules test` が通る。
3. **欄**(済み。2026-09-19。`Sources/QooMetaKit/BookMetadata.swift`): `BookMetadata`(タイトル、著者・ジャンル・関連・キーワード A〜C の並び、種類、メモ、シリーズ、巻 = 表記と数)。
   - 終わりの条件: 型とテスト(合成した値)。
4. **ファイル名フォーマット**(済み。2026-09-19。`Sources/QooMetaKit/FilenameFormat.swift`、集計は `qoometa formats`): 予約語 `@title @author @genre @source @keywordA @keywordB @keywordC @type @ignore`、型の並び
   (上から、名前全体に一致した最初のもの)、並びの欄の区切り(既定は括弧・`,`・`、`。設定で足せる)、最も近い型、同梱の型の並び(filename-format.md の 5)。フォルダ名は読まない。
   照合は qooMeta で書く(QooFormat は使わない)。filename-formats.json と規則の検証の予約語(`@event` `@circle` …)は、今の前段が読んで
   いて指紋の確かめに要るので、前段と一緒に段階 6 で直す(同梱の並びは、それまでコードの `FilenameFormats.presetTexts` に持つ)。
   - 終わりの条件: filename-format.md の 1・2・5 の書き方それぞれに合成した名前のテスト(`[@author (@author)]`、最後の ` - ` で分ける、
     全角の括弧、合わない名前で最も近い型が出る)。手元の蔵書で、型ごとの一致冊数と、どの型にも合わなかった冊数を報告する。
5. **画面の骨組み**(架空のデータ `-demo` だけ): 値の列(冊数・「(空)」)、1 冊 1 行の一覧、詳細(ファイル名の色分け・一致した型)、
   複数選択でまとめて書き換える操作。読むだけ + まとめて書き換えまで。シリーズと巻は段階 2 の中核を仮につないで出す。
   - 終わりの条件: **利用者が画面を見て、この方向でよいと言う**。ダメならここで直す(段階 6 以降を積む前に)。
6. **前段を差し替える**: 中核の入口へ、段階 4 のフォーマットで読んだ欄を渡す。examples.json を新しい欄と型に書き換える
   (期待値の `circle` `event` をやめ、ジャンルの語彙を外す)。
   `Sources/QooFormat` と古い前段を消し、正規表現の危険な形の検査を qooMeta のものに替える。
   - 終わりの条件: `import QooFormat` がどこにも無く、Package.swift・README・LICENSE から QooFormat の記述が消えている。
     組み込みの規則が新しい検査で読み込める。例のファイルが通る。手元の蔵書で、段階 1 との違いを**原因別の集計**で報告する(単位が変わった冊数 = 書き手・ジャンルの
     読みの違い、比べるタイトルが変わった冊数、シリーズ・巻が変わった冊数)。書き手が空の単位の冊数と、`qoometa bench` の速さも報告する。本ごとの記録はソルト付きのハッシュでリポジトリの外へ。
     filename-formats.json を新しい形に直し(同梱の並びをそこへ移す)、規則の検証の予約語を新しいものにする。
7. **修正と確定**: 欄ごとの「提案 / 直した値」、まとめて編集(ジャンル・著者の先頭・関連・タイトルを直したら、関わる単位のシリーズを
   組み直す。大量に直したときは 1 冊ずつではなく一括で計算し直す)、シリーズの操作(1 つにする・外す・巻を確かめる)、変更の索引、取り消し。
   - 終わりの条件: 合成した一覧で「全選択してジャンルを書き換える → 割れていたシリーズが 1 つになる」テストと、
     「方針 `differentGenre` を `keep` にする → ジャンルが違っても 1 つのシリーズになる」テスト。
8. **作業ファイル**: 開いたファイルの一覧と修正。アプリの設定(型の並び・規則の差分・スタンプ)とは分ける。ライブラリは持たない。
9. **書き出し**: qooViewer の JSON、StackNest・ShelfRow 向けの Stackroom XML(StackNest 向けのシリーズの分け方と仮の巻番号)。
   書き出しのプレビュー(欄が落ちるところに印)。
   - 終わりの条件: 合成したデータの書き出しを、各アプリの取り込みの形式と突き合わせるテスト。
10. **CLI**: 集計だけを出す検証・一括処理。
11. **アプリの残り**: スタンプ、適用前のプレビュー、型の編集の窓、規則の方針の設定(ジャンルで分けるかどうか …)、
    書き出しの画面(metadata.md の 4)。
12. **後回しにできるもの**: フォーマットの取り込み・書き出し(StackNest・ShelfRow・qooViewer)、ShelfRow の取り込みで関連がメモに
    入ることへの対処(中身が決まっていない)。
