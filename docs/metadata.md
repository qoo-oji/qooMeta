# メタデータの調査と提案

2026-09-19。qooMeta の目的は、**qooViewer・StackNest・ShelfRow が本を管理するためのメタデータを作ること**(qooViewer はそれを
EPUB・PDF・CBZ への書き出しにも使う)。そこで、3 つのアプリが**ファイル名から何を取り出し、何を管理に使っているか**をソースで調べた
(qooViewer は手元のリポジトリ `4b912b1`、StackNest は shelfsmith/stacknest、ShelfRow は umberbyte/ShelfRow `7355a41`)。
qooMeta が扱う欄は、ここから決める。どこにも当てはまらない雑多な情報をどうするかは、利用者が決める。

**2026-09-21 に、欄と書き出し先の表を実装(`Sources/QooMetaKit/BookMetadata.swift`・`Sources/QooMetaExport/FieldMapping.swift`)と
突き合わせて直し、4 の画面の節を今の画面に合わせた。** 1 の調査の結果は、調べた時点の記録のまま。

## 1. 調べた結果

### ファイル名から取り出すもの

| | qooViewer | StackNest | ShelfRow |
|---|---|---|---|
| 仕組み | 利用者が編集できる「ファイル名フォーマット」(上から順に照合)+「除外文字列」(正規表現)+「巻数フォーマット」(タイトル末尾の正規表現)。書き出し画面だけは固定の簡易な読み方(最初の角括弧 = 著者) | 利用者が編集できるテンプレート(ライブラリごとに名前付きで複数、監視フォルダ・追加ごとに選べる)。シリーズと巻は固定の正規表現 | 利用者が編集できるフォーマット 1 つ(既定 `[@author] @title`)。合わなければ固定の読み方 `(ジャンル)[作者]タイトル` |
| 予約語 | `@author` `@title` `@ignore` | `@title` `@author` `@genre` `@keywordA` `@keywordB` `@keywordC` `@relation` `@type` `@series` `@volume` | `@title` `@author` `@genre` `@keywordA` `@keywordB` `@relation` `@type` |
| 取り出して使う欄 | 著者・タイトル・シリーズ・巻 | 題名・作者・ジャンル・キーワード A/B・関連(ネタ)、シリーズ・巻(固定の正規表現) | 題名・作者・ジャンル・キーワード A/B・関連・種類 |
| 読まないもの | フォルダ名(本そのもののフォルダ名は読む) | 親フォルダ名。テンプレートの `@series` `@volume` `@keywordC` `@type` は取り込みで捨てる | 親フォルダ名。固定の読み方では末尾の `(関連)` を読まず、末尾の `[DL版]` などは捨てる |

### 管理に使う欄

| 欄 | qooViewer | StackNest | ShelfRow | 書き出し(qooViewer) |
|---|---|---|---|---|
| タイトル | 表示・検索・並べ替え | 検索・並べ替え・スマート本棚・一覧 | 検索・並べ替え・スマート本棚 | EPUB `dc:title`、PDF Title・XMP、ComicInfo Title |
| 著者 | 1 つ。表示「[著者] タイトル」・検索 | **複数**(`, ` 区切り)。絞り込みの列・スマート本棚・並べ替え | 1 つ。検索・並べ替え・スマート本棚 | EPUB `dc:creator`、PDF Author・XMP、ComicInfo Writer・Penciller |
| ジャンル | — | 複数。絞り込みの列など(利用者は本の種別に使っている) | 検索・並べ替え・スマート本棚 | (CBZ は元の ComicInfo の Genre を引き継ぐだけ) |
| 関連(ネタ) | — | 複数(`neta`)。絞り込みの列など | `relation`。検索など | — |
| キーワード A・B | — | 複数。絞り込みの列・スマート本棚・スタンプ | 検索・スマート本棚 | — |
| キーワード C | — | 複数。絞り込みの列(全文検索の対象外。CLI の `set` では設定できない) | **無い** | — |
| シリーズ | 1 つ(検索) | 1 つ。絞り込みの列・並べ替え(シリーズ → 巻)・前後の巻へ移動・重複検出 | **無い** | EPUB `belongs-to-collection`・`calibre:series`、PDF XMP、ComicInfo Series |
| 巻 | 文字列(「上」も可) | **数だけ**(CLI の `set` は整数だけ) | **無い** | 数に読めれば EPUB・PDF へ、CBZ は文字列のまま Number |
| メモ | — | 検索・スマート本棚 | 検索 | — |
| 種類(厚い本・薄い本 …) | — | ページ数などで自動 | テンプレートの `@type`、無ければページ数で自動 | — |

- 評価・未読・登録日・最後に読んだ日・ページ数・読み方向は、各アプリが本を開いて持つ情報で、ファイル名からは作らない。
- 埋め込みのメタデータ: qooViewer は EPUB・PDF・ComicInfo から、タイトル・著者・シリーズ・巻だけを取り込む(ComicInfo の残りは CBZ の
  書き出しで引き継ぐだけ)。StackNest は EPUB のタイトル・著者だけ。ShelfRow は読まない。
- 受け渡しの口:
  - qooViewer: JSON(著者・タイトル・シリーズ・巻)。**ファイル名フォーマット・除外文字列・巻数フォーマットも JSON で持ち運べる**。
  - StackNest: Stackroom XML の取り込み(新しいライブラリになる)、HTTP API・CLI・MCP での欄の書き換え。
  - ShelfRow: Stackroom XML の取り込みだけ。その取り込みでは **Neta をメモへ入れ、Genre と関連は空にする**。

## 2. qooMeta の欄(実装済み。`BookMetadata`)

3 つのアプリが管理に使う欄の和集合だけを扱う。言葉は 3 つのアプリ(Stackroom 系)に合わせる。

「利用先へ」は既定の対応表での行き先(下の「書き出し先ごとの欄の対応」。利用者が変えられる)。

| 欄 | コード | 中身 | 利用先へ(既定) |
|---|---|---|---|
| タイトル | `title` | | 全部 |
| 著者 | `authors` | **並び**(読み取った順) | StackNest へは並びのまま。qooViewer・ShelfRow へは先頭だけ(残りは捨てる) |
| ジャンル | `genre` | 1 つの値 | StackNest だけ(ShelfRow の取り込みはジャンルを読まない) |
| イベント | `event` | 1 つの値(頒布会の名前) | どれにも無い(既定では落ちる。2026-09-20、利用者の判断で足した) |
| 原作 | `source` | 1 つの値(二次創作の元の作品。2026-09-20 に「関連」から名前を改めた。ShelfRow の `relation` に引っ張られた名前だったため) | StackNest のネタ(`Neta`)・ShelfRow のメモ(`Neta`) |
| 情報 | `info` | 1 つの値(名前の中の付記など。2026-09-20 に「メモ」から改めた) | StackNest のキーワード A(StackNest の取り込みにメモの欄は無い)。qooViewer・ShelfRow では落ちる |
| シリーズ | `series` | ファイル名からは読まず、中核の規則で導く(名前にはっきり書いてあれば `@series`) | qooViewer・StackNest のシリーズ、ShelfRow のキーワード A |
| 巻数(表示用) | `volume` | 名前に書かれていた表記(「第01巻」「上」「総集編2」)。数に読めなくてもよい | qooViewer の `seriesIndex`、StackNest のキーワード C、ShelfRow のキーワード B |
| 巻数(ソート用) | `volumeSort` | シリーズの中の位置(数。読めなければ空) | StackNest の巻数(`Volume`)。qooViewer・ShelfRow では落ちる |

- 空の欄は空の文字列・空の並びで表す(「無い」と「空」を分けない。絞り込みでは、どちらも「(空)」)。
- 巻数(表示用)を書き換えると、巻数(ソート用)は捨て、表記を巻の読み手に通して読み直す(食い違った数を残さない)。

- **著者が複数なのは、名義が複数だから**(商業でも原作と作画が別、同人誌でもサークル名・原案・作画が併記される)。型で著者の欄に入った
  文字列を、括弧・カンマ・「、」などの区切りで分け、出てきた名前を順に並びへ入れる(`[サークル (作画、原案)]` なら「サークル」「作画」
  「原案」)。区切りの文字は設定で変えられる。並びをどう使うかは利用先のアプリ次第で、欄が 1 つしかない利用先へは先頭だけを渡す。
  **並びは著者だけ**(2026-09-19)。StackNest はジャンル・関連・キーワードも `, ` 区切りの複数値で持てるが、それは StackNest の作りで、
  qooMeta に要る理由が無い(名義が本当に複数ある著者とは違う)。1 つの値として持ち、StackNest へもそのまま渡す。
- ファイル名の読み方(型)の予約語は、この欄に合わせる: `@title` `@author`(何度でも書け、書いた順に著者の並びになる)`@genre`
  `@event`(頒布会の名前)`@source`(StackNest・ShelfRow の `@relation`)`@info`(ほかの欄のどれでもない部分)、読んで捨てる `@ignore`。
  シリーズと巻は、ふつうはタイトルから規則の JSON で導く(filename-format.md の 3)。**名前にはっきり書いてあるときだけ** `@series`
  `@volume` で読み、利用者が確定した値と同じ扱いにする(2026-09-20、利用者の判断。filename-format.md の 2)。StackNest・ShelfRow・
  qooViewer のテンプレートと同じ言葉なので、利用者が使っている型をそのまま持ってこられる(取り込みの機能はまだ無い。roadmap.md の段階 12)。
- **シリーズと巻を、ほかの本と見比べて補う**のが qooMeta の役目(3 つのアプリはどれも 1 冊ずつ、タイトルの末尾から読むだけ)。
  今の仕組み(著者の並びの先頭が同じ本どうしで比べる)は、この欄の上でそのまま使える。
- 種類(ShelfRow の `@type`)は欄にしない(2026-09-20)。決まった 6 つ(厚い本・薄い本・本の一部・画像セット・テキスト・ムービー)から
  選ぶ値で、ふつうはページ数で自動に決まる。qooMeta はページ数を知らず、ファイル名に種類を書く命名もまず無い。

### 書き出し先ごとの欄の対応(2026-09-20 決定)

ファイル名の読み方は 1 つ(qooMeta の欄に読む)。書き出し先のアプリごとの違いは、**書き出しの対応表**で振り分ける。
StackNest・ShelfRow のキーワード A〜C は qooMeta の欄にしない(2026-09-20)。対応表の行き先として、どの欄でも入れられるようにする
(例: StackNest へは、イベントをキーワード A へ)。対応表は書き出し先ごとに
既定を持ち、利用者が変えられる(アプリの設定として持つ)。直した内容は作業ファイルに残るので、使うアプリを乗り換えたら出力し直せばよい。

**2026-09-20 に、3 つのアプリの取り込みのコードを読んで数え直した**(StackNest の `StackroomFormat/BookRecord.swift` と
`LibraryStore/LibraryImporter.swift`、ShelfRow の `ShelfRow/LibraryImporter.swift`、qooViewer の `Services/LibraryJSONSchema.swift`)。
**読まない欄へ渡すと、書き出しは成功するのに値だけが消える**ので、行き先に出さない。

- **StackNest が読む欄**: Title・Author・Genre・Series・Volume(数)・Neta・Keyword A / B / C(ほかに ID・Path・日付・種別)。
  **`Memo` という欄は取り込みに無い**(StackNest 本体はメモを持つが、Stackroom XML からは渡らない。取り込みは nil を入れる)。
- **ShelfRow が読む欄**: Title・Author・Keyword A・Keyword B・**Neta(ShelfRow の「メモ」になる)**。
  **Genre・Series・Volume・Keyword C は読まない**(ジャンルは取り込みで必ず空になる)。
- **qooViewer が読む欄**: author・title・series・seriesIndex(`formatVersion: 4` の `metadata`)。

| qooMeta の欄 | qooViewer | StackNest(Stackroom XML) | ShelfRow(Stackroom XML) |
|---|---|---|---|
| タイトル・著者 | 著者は先頭だけ | 著者は並びのまま(`, ` でつなぐ) | 著者は先頭だけ |
| ジャンル | (落ちる) | ジャンル | 既定は落とす(行き先が残っていない) |
| イベント | (落ちる) | 既定は落とす(キーワード B へ回せる) | 既定は落とす |
| 原作 | (落ちる) | ネタ(Neta) | **メモ(Neta)** |
| 情報 | (落ちる) | **キーワード A**(メモの欄は取り込みに無い) | 既定は落とす |
| シリーズ | そのまま | シリーズ | **キーワード A**(シリーズの欄が無いため。2026-09-20、利用者の判断) |
| 巻数(ソート用。数) | (落ちる。数の欄が無い。qooViewer 側を拡張するかは未決) | 巻数(数の欄なのでそのまま) | (欄が無い) |
| 巻数(表示用。表記) | `seriesIndex`(文字列の欄) | キーワード C | キーワード B |

落ちる欄は、書き出しのプレビューで印を付けて見せる(値のある冊数つき)。**書き出したキーが、そのアプリの読む欄だけであること**は
テストで確かめている(`everyKeyWeWriteIsOneTheAppReads`)。

### 書き出し先ごとのシリーズと巻

**巻数は 2 つ持つ**(2026-09-20、利用者の判断)。

| | 型 | 中身 | 例 |
|---|---|---|---|
| 巻数(ソート用) | `Double?` | シリーズの中の位置 | 「架空タイトル 第01巻」なら `1.0`。収録範囲の読めた総集編「X 総集編 1~4」を本編の後ろに置く設定なら `4.5` |
| 巻数(表示用) | `String` | 名前に書かれていた表記 | 「第01巻」「上」「総集編2」 |

**総集編は、シリーズに含める / 含めないを設定で切り替える**(2026-09-20、利用者の判断)。切り替えは方針 `compilations` で、
「抽出の設定」の窓で選ぶ(画面で変えた設定は規則の差分として持つ。同梱の既定は 2026-09-21 から `inMainSeries` = 含める)。

- 含めるときも、**巻数(表示用)は「総集編1」のまま、巻数(ソート用)は空**(方針 `compilationVolume` = `none`)。収録範囲が読めたときだけ、
  その最後の巻の直後にできる(`afterRange`。「1~4」なら 4.5。名前に書いてある範囲から導くので、作った数ではない)。含めないときは、
  これまでどおり別のシリーズ(「X 総集編」)にする。
- **はじめは任意のオフセットを足していた**(オフセット 100、総集編 2 なら 102.0。番外編も同じ)が、名前のどこにも書いていない数なので、
  後に利用者の判断で捨てた(roadmap.md「巻数は分かる順番だけ」)。番外編は総集編の語から外した。
- **「フルカラー総集編」は、総集編とも重複とも見なさない**(2026-09-20)。独立した 1 冊として扱う。
- **特装版・フルカラー版などの版違いは、巻にしない。** 中身は同じ本なので、シリーズの巻としてではなく、**同じ本の重複**として扱う
  (今の中核と同じ: 版の印を除いた比べるタイトルが同じ本だけの組は、シリーズにしない)。重複は、一覧で印を付ける(または強調する)だけにする。
- **番号の無い本**: 同じシリーズに 2 以上の番号があって 1 が無く、候補が 1 冊に決まるときだけ 1 巻と推定する(方針 `unnumberedFirst`)。
  巻数(ソート用)は 1.0、巻数(表示用)はそのシリーズの書き方にそろえた 1 巻の表記(「1」「01」「I」「一」、位置の語なら対の最初の語)。
  それ以外の番号の無い本は、シリーズ名より後ろの文字をそのまま巻数(表示用)に入れ、巻数(ソート用)は空(方針 `unnumberedVolume`)。

書き出しは、上の対応表のとおり:

- **StackNest**: 巻数の欄は数なので、巻数(ソート用)をそのまま渡す。巻数(表示用)は、空いている欄(キーワード C など)へ回す。
- **ShelfRow**: 巻数の欄が無い。巻数(ソート用)は数だけでは意味が無いので捨て、巻数(表示用)を空いている欄(キーワード B・メモなど)へ回す。
- **qooViewer**: いまの JSON(`formatVersion: 4`)で渡せるのは巻数(表示用)だけ(`seriesIndex`)。巻数(ソート用)も持てるように
  qooViewer 側を拡張する想定だったが、まだ無いので既定では落ちる。
- EPUB・PDF・CBZ へは qooViewer が書き出す(qooMeta は qooViewer へ渡すだけ)。数に読める巻だけが渡る(qooViewer の作り)。

## 3. 雑多な情報の扱い

名前のどの部分を何の欄とみなすか(捨てるかを含む)は、**ファイル名フォーマットで利用者が決める**(`[@info]` なら情報、`[@ignore]` なら捨てる)。別の仕組みは作らない。フォーマットの提案は [filename-format.md](filename-format.md)。

## 4. 画面

### 調べたこと

| | StackNest | ShelfRow |
|---|---|---|
| 構成 | 左: サイドバー(ライブラリ・お気に入り・最近・シェルフ・スマートシェルフ)。中: 上ペイン(絞り込みの列 3 本 / スタンプ / 隠す)+ 一覧(リスト・グリッド)。右: 詳細ペイン(常に表示) | 左: サイドバー(すべて・未読・シェルフ・スマートシェルフ)。中: 一覧(リスト・グリッド)と見出し(件数・並べ替え・検索・絞り込みのチップ)。右: 1 冊のインスペクタ |
| 探す | サイドバーの範囲・フィルタ(種類・未読・評価・日付)・絞り込みの列・検索を AND で重ねる。絞り込みの列は左の列の選択で右の列の候補が絞られる(ジャンル・シリーズ・著者・関連・KW A〜C から選ぶ)。**値ごとの冊数も「(空)」の行も無い** | 検索(7 つの欄、同一視の規則で広げる)、スマート本棚(条件の AND)、絞り込みのチップ |
| 一覧 | 列の表示・順序・幅を変えられ、見出しで並べ替え(シリーズは シリーズ → 巻)。**セルでは編集しない** | 列の表示を変えられ、見出しで並べ替え |
| 直す | 詳細ペイン。複数値の欄はチップ。**複数選択でまとめて編集**(値が揃わない欄は「<複数値>」、入力すると全冊のその欄を置き換える)。スタンプで値を**足す**。チップの「→」でその値の絞り込みへ飛ぶ。すべて取り消せる | インスペクタで 1 冊ずつ。まとめて編集・取り消しは無い |
| ファイル名から補う | 空の欄だけを埋め、プレビュー無しで適用(取り消せる)。**適用前のプレビューがあるのはファイル名の変更だけ**(旧名 → 新名、問題の行に印) | 空の欄だけを埋め、プレビュー無し |

どちらも**ライブラリを管理するアプリ**の画面で、サイドバー(シェルフ・お気に入り・最近・スマート本棚)、評価・未読・日付の絞り込み、
グリッドや読むための操作は、ライブラリを持ち続けることが前提になっている。**qooMeta にはライブラリが無い**(開いたファイルの一覧から
メタデータを作り、確かめて直し、書き出すだけ)ので、これらは取り入れない。取り入れるのは「一覧で見つけて、選んで、詳細でまとめて直す」
流れと、StackNest のファイル名の変更の「適用前に全件の変化を見せる」やり方。

### 今の画面(実装済み。2026-09-21)

はじめの案(2026-09-19。一覧を中心に、右に詳細)の方向はそのままで、その後の利用者の指摘で次のように変わった。
流れ・窓・コードの置き場所の詳細は [design.md](design.md)「アプリ」。

- **1 回きりの流れ**にした(2026-09-21、利用者の指摘「固定の蔵書を繰り返し処理する道具ではない」)。窓の上の段のバーで
  **1 対象を選ぶ → 2 解析方法を選ぶ → 3 確認・編集 → 4 書き出す** を進む。段 2 を通るまで一覧は出さない(既定のルールセットを
  黙って当てない)。段 2 は、ルールセットごとに読み切れた冊数を見せて選ばせ、本ごとに選ぶ「自動」も並べる。
- **段 3 の一覧**(`NSTableView`): 1 冊 1 行。列は qooMeta の欄とファイル名(ファイル名は隠せない)。列の表示・順序・幅は覚え、
  **どの列も見出しで昇順・降順に並べ替えられる**。**セルを 2 回押すとその 1 冊の欄を直せる**(はじめの案の「セルでは編集しない」を
  利用者の指示で改めた。ファイル名と巻数(ソート用)は読むだけ。巻数はシリーズ名のある本だけ)。直した欄は色を変え、
  どのフォーマットにも合わなかった本は灰色にする。**右クリックで、選んだ本を別のルールセットで読み直せる**。
  - 一覧の上の絞り込み: **ジャンル → 著者**(値ごとの冊数と「(空)」つき)、**本の状態**(シリーズに入っていない / 巻が空 /
    フォーマットに合わない / 直した / シリーズを確定した)、検索(欄とファイル名)。絞り込んで全選択すれば、まとめて直す単位になる。
  - シリーズは絞り込みに使わない(導いた結果なので、確かめるのは並べ替えと状態の絞り込みで)。
- **段 3 の右の詳細**: 欄の編集(複数選択なら、揃わない欄は「複数の値」、入力すると選んだ全冊のその欄を置き換える)、欄ごとに
  「提案に戻す」、スタンプ、シリーズの操作(1 つにする・巻を決める・確定する・外す・巻を消す・提案に戻す・連番を振る)、
  ファイル名のどの部分がどの欄になったか(一致した型。合わなければ、いちばん近い型と外れた位置)。
- **スタンプ**(StackNest): 選んだ本へ、登録した欄の値をまとめて入れる。登録した値はアプリの設定に持つ。
- **取り消し**: 直したことはすべて取り消せる(⌘Z)。
- **適用前の確かめ**: シリーズの操作で**選んでいない本まで動く**ときだけ、動く冊数を見せて確かめる。規則の変更は、開いている一覧へ
  すぐ効く(全件の「今 → 変えた後」を見せてから適用する形にはしていない)。ファイル名の解析を直した効果は、「解析の設定」の窓の
  名前の確かめで、保存してある版と下書きを行ごとに見比べる。
- **設定の窓は 2 つ**(当たる処理の段が違うので分けた): **「解析の設定」**(ファイル名の解析。ルールセットの編集、どの名前が
  読み切れないかと問題の位置)と **「抽出の設定」**(シリーズと巻数の抽出。困りごとから設定へ進む「やりたいこと」、方針、語の規則、
  巻の読み手、語の一覧)。どちらも差分(JSON)を直に書ける。
- **段 4 の書き出し**: 書き出し先(qooViewer の JSON / StackNest・ShelfRow 向けの XML)を選ぶと、欄ごとの行き先を対応表で見せ、
  値があるのに落ちる冊数・著者が先頭だけになる冊数に印を付ける。対応表を変えると数がその場で変わる。

取り入れないもの(はじめの案のまま): サイドバー(シェルフ・スマート本棚・お気に入り・最近)、評価・未読・日付、グリッド表示と
読むための操作、これまでの「推定」「総集編」「版の印」の絞り込み。はじめの案にあった、詳細の値の札の「→」で一覧の絞り込みへ
飛ぶ操作は、作っていない(並びの欄は行ごとの入力と並べ替えのボタン)。

## 5. 決まったこと・決めてほしいこと

決まったこと(2026-09-19):

- 欄は 3 つのアプリが管理に使う欄の和集合(2 の表)。
- 著者は、区切りで分けた名前の並び(読み取った順。並びは著者だけ)。どう使うかは利用先次第で、1 つしか持てない利用先へは先頭だけを渡す。
- 巻は表記と数の両方を持つ。中では qooViewer の考え方(総集編も同じシリーズで、巻の表記で区別)。StackNest へは、総集編などの
  シリーズを分け、巻は表記の中の番号か仮の番号(ファイル名の順・作成日の順)にする。
  (注: 後の決定で改めた。書き出し先ごとに分け方を変えず、対応表で欄を振り分けるだけ。仮の番号は作らない。2 の「書き出し先ごとのシリーズと巻」)

- 画面は 4 の方向で進める(合わなければ利用者が指摘する)。2026-09-21 までの指摘を入れた今の画面が 4 の「今の画面」。

決めてほしいこと: なし(roadmap.md)。
