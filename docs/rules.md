# 規則ファイルの説明書

qooMeta の規則は、次の 2 つの JSON に書かれています。どちらもパッケージに同梱され、`qoometa` はこれを読み込んで動きます。

| ファイル | 役割 |
|---|---|
| [`Sources/QooMetaCore/Resources/filename-formats.json`](../Sources/QooMetaCore/Resources/filename-formats.json) | ファイル名を**どう区切り、どこが何の欄か**(サークル・作者・タイトル・ネタ …)を決める |
| [`Sources/QooMetaCore/Resources/series-rules.json`](../Sources/QooMetaCore/Resources/series-rules.json) | 読み取ったタイトルから**シリーズ名と巻**を取り出す |

処理の順は「ファイル名 → (filename-formats.json)→ 欄 → (series-rules.json)→ シリーズと巻」です。

## 共通の注意

- **編集したらビルドし直してください**(`swift build -c release`)。JSON はビルド時にパッケージへ取り込まれます。
  利用者ごとの上書きファイルは、まだ用意していません。
- **蔵書の名前(書名・サークル名・フォルダ名)を書かないでください。** この 2 つのファイルは公開リポジトリに含まれます。
  書いてよいのは一般的な語と記号だけです。コミット時の検査(`scripts/ci/check-private-terms.sh`)が、手元の禁止語の一覧と照合します。
- 本の種別の名前(ファイル名の先頭の丸括弧に書く分類)は、蔵書のフォルダ名と同じ語であることが多いので、ここではなく
  リポジトリの外の `~/Library/Application Support/qooMeta-dev/config.json` の `mediaTypes` に書きます。
- タイトルどうしの比較と、`labelIntroducers`・`notFirstMarkers`・`notFirstPrefixes` の照合は、全角・半角と大文字・小文字を
  そろえてから行います。版・入手経路の印(`editions`)と巻の読み方(`volume` のほかの語)は、書いたとおりの表記で探します
  (全角の `ＤＬ版` は `sourcePatterns` の正規表現で受けています)。英字の語は大文字・小文字を区別しません。
- 語の一覧は、長い語から先に照合するよう自動で並べ替えます。書く順は気にしなくてかまいません
  (`formats` だけは書いた順が優先順位です)。
- 変えたあとは、次で結果を確かめてください。
  - `swift test` — 合成した名前での単体テスト
  - `qoometa scan …` → `qoometa stats …` — 手元の蔵書での集計(名前は出ません)
  - `qoometa evaluate --corpus …` — 公開データでの採点(README「公開データでの検討」)

## 1. filename-formats.json

ファイル名(拡張子を除いたもの)を、フォーマットに当てはめて欄に分けます。照合の処理は qooLibrary のもの
(`Sources/QooFormat`)で、正規表現をつなげるのではなく、括弧の入れ子を保ったまま前後から当てはめます。

### 例

```
(種別A) [架空工房 (山田太郎)] 月の庭 2 (作品A) [DL版]
  ↓ "(@genre) [@circle (@author)] @title (@relation) [@keywordA]"
@genre = 種別A   @circle = 架空工房   @author = 山田太郎
@title = 月の庭 2   @relation = 作品A   @keywordA = DL版
```

### キー

#### `version`(数)

ファイルの形式の版。今は `1`。

#### `reservedWords`(オブジェクト)

フォーマットの中で使う予約語と、その意味。予約語は Stackroom(StackNest・ShelfRow)の呼び方に合わせています。

| 予約語 | `field`(qooMeta の欄) | 意味 | 書き出し先 |
|---|---|---|---|
| `@genre` | `genre` | 先頭の丸括弧。本の種別(同人の本・商業の単行本 などの分類) | Stackroom XML の `Genre`。**本の種別が違う本は同じシリーズにしない** |
| `@event` | `event` | 先頭の丸括弧のうち、本の種別の語彙に無いもの(頒布イベント名) | (書き出さない) |
| `@circle` | `circle` | サークル | CSV の「サークル」、Stackroom XML の `Author`(1 つ目)、qooViewer の著者 |
| `@author` | `authors` | 作者(`authorSeparators` で複数に分ける) | CSV の「作者」、Stackroom XML の `Author`(2 つ目以降) |
| `@title` | `title` | タイトル | シリーズ名と巻はここから取り出す |
| `@relation` | `relation` | 末尾の丸括弧。元になった作品(ネタ、関連) | CSV の「ネタ」、Stackroom XML の `Neta`。**ネタが違う本は同じシリーズにしない** |
| `@keywordA` | `keyword` | 末尾の角括弧 | (今は書き出さない) |

`@circle` と `@event` は Stackroom に無いので qooMeta で足した予約語です。

各予約語の `engine` は、照合の処理(qooLibrary)での呼び名です。**`engine` と `field` は処理と結び付いているので、
変えないでください。** 変えてよいのは、予約語の綴り(左側のキー)だけです。キーを変えたら、`formats` の中の綴りも合わせてください。

`@genre` と `@event` の見分け方: どちらも先頭の丸括弧ですが、中身が `config.json` の `mediaTypes` にある語なら `@genre`、
無ければ `@event` として読みます(`@genre` のフォーマットが先に試され、語彙に無いと一致しないため)。

#### `delimiters`(配列)

区切りとして扱う括弧の組(`["開き", "閉じ"]`)。既定は `[ ]` と `( )` だけです。

`【】` `「」` `（）` はタイトルの一部として使われることが多いので、区切りにしていません。足すと、タイトルの途中の括弧で
誤って区切られることがあります。

#### `authorSeparators`(文字列)

`@author` の中で、作者を分ける文字。1 文字ずつが区切りになります。既定は `、` `,` `，` `&` `＆` `/` `／`。

#### `formats`(配列)

フォーマット。**上から順に試し、最初に一致したものを採ります**(書く順が優先順位)。

- 予約語以外の文字(括弧・空白・その他の文字)は、そのまま照合します。
- 空白は「0 文字以上の空白」として照合します。
- 1 つのフォーマットに同じ予約語は 1 回だけ。`@title` の無いフォーマットは、タイトルが空になるので qooMeta では役に立ちません。
- 隣り合う 2 つの予約語(`@title@relation` のように区切りが無いもの)は書けません(どこで切るか決まらないため)。
- どのフォーマットにも一致しない名前は、qooMeta 自身の簡易な解析(`(A) [B (C)] T (D)` の形を探す)へ回ります。

**欄の多い形を先に、少ない形を後に**書いてください。`… @title` を `… @title (@relation)` より先に書くと、末尾の
`(ネタ)` までタイトルに入ってしまいます(`@title` は残り全部に一致できるため)。

#### `protectedTokens`(配列)

1 かたまりとして扱う文字列(正規表現)。ここに一致した部分は、区切りの括弧を含んでいても区切りとして扱いません。

既定は、タイトルの末尾の `(2019)` のような年と、`(完結)` などの語です。これが無いと、`月の庭 (2019)` の `(2019)` が
ネタ(`@relation`)として読まれてしまいます。

正規表現は JSON の文字列なので、`\` は `\\` と書きます。

## 2. series-rules.json

`@title` から、シリーズ名と巻を取り出します。処理の流れは次のとおりです。

1. **比べる単位**: 同じサークル(無ければフォルダ)で、本の種別(`@genre`)が同じ本どうしだけを比べます。
2. **組を作る 1 段目**: 「タイトル + 巻」の形の本(`X 2` `X 第3巻`)を、巻を除いた頭(`X`)でまとめます。
3. **組を作る 2 段目**: 残りを、タイトルの先頭の共通部分でまとめます。
4. **例外**: シリーズではない組を外します(ネタが違う、1 語だけの一致、版違いだけ …)。
5. **総集編**: 本編とは別の `X 総集編` のシリーズにします。
6. **名前**: 共通部分を元の表記に戻し、整えます。
7. **巻**: シリーズ名より後ろの部分から巻を読み、1 巻の推定などを行います。

### `version`(数)

ファイルの形式の版。今は `1`。

### `compare` — 比べ方

| キー | 型 | 意味 |
|---|---|---|
| `ignoredCharacters` | 文字列 | 比べるときに無視する文字。空白と、タイトルの飾りによく使う記号。1 文字ずつが対象 |
| `variantKanji` | オブジェクト | 比べるときに同じ字とみなす異体字(`"凜": "凛"` は「凜」を「凛」として比べる)。書き出す表記は変えない |

`ignoredCharacters` に長音記号「ー」を入れないでください(語の一部なので、落とすと別の語が同じになります)。

### `grouping` — 組の作り方と例外

| キー | 型 | 既定 | 意味 |
|---|---|---|---|
| `minPrefix` | 数 | 4 | タイトルの共通部分が**語の途中で**切れるとき、この文字数以上なら組にする。語の切れ目で切れるときは 1 文字でも組にする |
| `minWholeTitle` | 数 | 2 | 片方のタイトル全体がもう片方の先頭と一致するとき(`XY` と `XY2`)の最小文字数 |
| `attachSubtitled` | 真偽 | true | 副題付きの本(`X 〇〇編`)を、巻でまとめた `X` の組に入れる |
| `splitByGenre` | 真偽 | true | ネタ(`@relation`)が違う本を分ける。ネタの無い本はいちばん大きい組へ入れる |
| `rejectHiraganaEndings` | 真偽 | true | 語の途中で切れる共通部分が、ひらがな(助詞など)で終わるなら組にしない |
| `rejectSingleWordPrefixes` | 真偽 | true | 語の途中で切れる共通部分が 1 種類の文字だけ(カタカナだけ、漢字だけ …)なら組にしない |
| `rejectCommonEnglishTitles` | 真偽 | true | 2 冊とも一般的な英単語だけでできたタイトルなら組にしない(後ろに巻があれば組にする) |
| `englishDictionary` | 文字列 | `/usr/share/dict/words` | 一般的な英単語の一覧(1 行 1 語)。無ければ、どの語も一般語とみなさない |
| `boundaryCharacters` | 文字列 | (記号の並び) | 語の切れ目とみなす記号。空白と数字は常に切れ目 |

例外を 1 つずつ `false` にして、`qoometa evaluate` や手元の集計で効き目を比べられます。

### `naming` — シリーズ名の整え方

| キー | 型 | 意味 |
|---|---|---|
| `trimTrailing` | 文字列 | シリーズ名の**末尾**から落とす記号(先頭は落とさない) |
| `keepFollowing` | 文字列 | 共通部分のすぐ後ろにあれば、シリーズ名に含める文字(`月の庭！` の `！`) |
| `brackets` | オブジェクト | 閉じ括弧 → 開き括弧。シリーズ名に開いたままの括弧があれば、すぐ後ろの閉じ括弧まで含める(`【X】`) |
| `labelIntroducers` | 配列 | シリーズ名の最後の 1 語がこの語なら外す(`X side A` と `X side B` のシリーズ名は `X`) |

### `editions` — 版と入手経路

タイトルの中の印です。**比べるときは印を除いたタイトルを使い、印を除いて同じタイトルになる本は同じ作品とみなします。
同じ作品だけの組はシリーズにしません。** シリーズの中の版違い(`X 3【フルカラー版】`)は、元の本と同じ巻になります。

| キー | 型 | 意味 |
|---|---|---|
| `edition` | 配列 | **版**: 内容(色・収録内容・修正・言語など)が違う同じ作品。CSV の「版」、Stackroom XML の `Keyword C` に書く |
| `editionPatterns` | 配列 | 版の印の正規表現(既定は `〇〇語版`) |
| `source` | 配列 | **入手経路**: 内容は同一で、手に入れた経路だけが違う。CSV の「入手元」に書く |
| `sourcePatterns` | 配列 | 入手経路の印の正規表現(既定は `DL版`。全角も) |

印は、`【】` `[]` `()` に入っていても、空白の後ろに付いていても見つけます。特装版・通常版は、付録の違いだけで本体は
同じなので入手経路に入れています。

### `compilation` — 総集編

| キー | 型 | 意味 |
|---|---|---|
| `keywords` | 配列 | 総集編を示す語。タイトルにこの語がある本は、本編とは別の `X 総集編` のシリーズにする |

- 番号の有無で分け方を変えません(番号の無い最初の総集編のあとに `総集編2` が出ることがあるため)。
- 総集編が 2 冊以上あるか、同じサークルに本編のシリーズ `X` があれば、1 冊でもシリーズにします。
- 総集編の語の前に書かれた範囲(`X1~4総集編`)は、`X 総集編` の巻 `1~4` として読みます。

### `volume` — 巻の読み方

巻は、表記(文字列。`36-37` や `上` もそのまま)と、並べ替え用の数に分けて持ちます。

| キー | 型 | 意味 |
|---|---|---|
| `prefixes` | 配列 | 巻の番号の前に付く語(`vol` `第` `その` …)。英字の語は後ろの `.` も受け付ける(`Vol.3`) |
| `counters` | 配列 | 巻の番号の後ろに付く単位(`巻` `話` `号` `月号` `弾` `つめ` …) |
| `wholeOnlyCounters` | 配列 | 「残りが巻だけか」を見るときにだけ使う単位(既定は `集`) |
| `kanjiCounters` | 配列 | 漢数字の後ろに付く単位(`一巻` `三話`)。漢数字はこの単位か、`prefixes` のうち日本語の語(`第` `その` …)が前に付くときだけ読む |
| `positionWords` | オブジェクト | `first`(上・前編 …)、`middle`(中・中編 …)、`last`(下・後編 …)。シリーズに `middle` の語があれば 上1・中2・下3、無ければ 上1・下2。`後編1` のような番号付きは 3.1 |
| `mergedIssueMaxSpan` | 数 | `36-37` を合併号(範囲)とみなす条件。後ろの数が前より大きく、差がこの値以下のときだけ範囲として読む(`2021-01` のような年月は範囲にならない) |
| `notFirstMarkers` | 配列 | シリーズ名より後ろにこの語がある本は、「番号の無い 1 冊を 1 巻とみなす」推定の候補にしない |
| `notFirstPrefixes` | 配列 | シリーズ名のすぐ後ろにこの語が付く本も、同じく候補にしない(`Xex` `X SP`) |

このほか、次の読み方は処理に組み込まれています(JSON には出していません)。

- `第` + 数字 + 任意の漢字 1 字(`第1幕` `第三部`)、分冊(`第04-1章` → 4.1)
- ローマ数字(大文字、1〜39)、ギリシャ文字(`α` = 1)、大字(壱弐参 …)と百・千
- 雑誌の号(`2025年36-37号` `2011年03月号` `2022 Vol.01`)。年はシリーズ名に残し、1 年ぶんを 1 シリーズにする
- 漢数字で始まるだけの形(`二〇` `三〇`)は、同じシリーズで巻の読めない本が 2 冊以上、違う漢数字で始まるときだけ読む
- 末尾の丸括弧が数字だけ(`X (12)`)なら、ネタではなく巻として読む

## 変更の例

**区切り語を足す**(`X route A` と `X route B` を `X` にまとめたい。`route` は既定に入っています):

```json
"labelIntroducers": ["side", "part", …, "route", "arc"]
```

**版の印を足す**(`X 【初版】` を版として扱いたい):

```json
"edition": ["フルカラー版", …, "初版"]
```

**フォーマットを足す**(先頭が `【@genre】` の命名にも対応したい): `delimiters` に `["【", "】"]` を足し、
`formats` に `"【@genre】 [@circle] @title"` を足します。既存の名前の読み方が変わらないか、`qoometa stats` で確かめてください。
